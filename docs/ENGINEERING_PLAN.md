# W0rkTree Engineering Plan & Contracts (v2 rebuild)

This document is the **binding contract** for the v2 rebuild. Every
workstream codes against the interfaces here. If you must change a contract,
keep the change additive and note it in your final report.

## 1. Target architecture

```
 wt (CLI, Rust) ──► worktree-sdk (Rust) ──► .wt/ on disk
      │                  │  remote (gRPC h2c + REST)
      │ ipc (JSON/TCP)   ▼
 worktree-bg (Rust) ──► worktree-server (Go, services/server-go) ──► bbolt meta + CAS objects
                              ▲ REST + SSE
                        apps/admin (React/Vite admin panel)
 worktree-git (Rust) — Git import/export over worktree-sdk
 apps/web (Next.js) — marketing + docs site
```

* **One server port** (default `7420`): gRPC (`application/grpc*`, HTTP/2
  cleartext h2c) and REST/SSE/static share it. Remote URLs look like
  `http://localhost:7420`.
* The Rust `crates/worktree-server` crate was **removed** (superseded by Go).
* The Yew `crates/worktree-admin` crate is **replaced** by `apps/admin`.

## 2. Wire protocol

`crates/worktree-protocol/proto/sync.proto` (`worktree.sync.v1.SyncService`)
is the Rust⇄Go contract. Regenerate Go code with `bash scripts/gen-proto.sh`;
Rust code is generated by `build.rs` (vendored protoc, no install needed).

* **Object hash** = BLAKE3-256 of exact bytes. `ContentHash.value` = 32 raw bytes.
* **Objects**: BLOB = raw file bytes; MANIFEST = protobuf-encoded
  `ManifestRecord` (entries sorted by path, unique, '/'-separated).
* **Snapshots** travel as `SnapshotRecord` (not objects). ids = UUID v4 strings.
* Auth: gRPC metadata `authorization: Bearer <token>`; anonymous allowed only
  for Ping and reads of public trees.
* **Push flow**: `ResolveTree(create_if_missing)` → `Pull`/`ListBranches` to
  learn remote tip → `UploadObjects` (manifests + blobs the server lacks; use
  `Negotiate` with `have` = candidate hashes, response `objects_to_send` =
  hashes the server is missing) → `Push{old_tip, new_tip, snapshot_chain,
  snapshots}`. Server checks: auth (tree:write), review.CheckPush, license
  CheckPush on changed paths, all referenced manifests/blobs present, every
  snapshot's parents known (already stored or in this request), new_tip
  descends from current server tip (else `ConflictDetected{server_tip}`), CAS
  on branch tip. On success clears pusher's staged entry for the branch,
  publishes `branch.pushed`, audits `branch.push`.
* **Pull flow**: `Pull{current_tip}` → server returns `snapshot_chain` +
  `snapshots` (missing ones, oldest first, `depth` limits count) and
  `objects_to_fetch` (all manifest + blob hashes referenced by those
  snapshots) → client `DownloadObjects(want = hashes it lacks)`.
* gRPC max message size: 64 MiB both directions.

## 6. Background daemon (`worktree-bg`)

Binary `worktree-bg` (`run [--foreground]`). IPC per `worktree_sdk::ipc`.
Config `$WT_HOME/bg.toml` `{ watched = ["path", ...] }` persisted on watch/unwatch.
Per watched worktree: `notify` watcher → debounce (`[auto_snapshot]`
inactivity / max files) → `Repository::snapshot(auto_generated=true,
message="auto: N files changed")` for each tree with changes → if
`[sync].auto_stage` and remote + credential exist, `remote::stage`.
Never snapshots during a merge in progress. Ignores events under `.wt/`.

## 9. Conventions

### 12.1 Authorization model

Package `internal/authz`: `authz.New(store domain.MetaStore, opts authz.Options) *authz.Authorizer`,
implementing `domain.Authorizer` and `domain.AccessEvaluator`. Evaluation for
(principal, action, resource):

1. Disabled account or disabled service account: deny.
2. Server admin: allow. Admins bypass policies, but token scopes still apply.
3. Token scopes: when `p.Scopes` is non-empty the action must match a scope
   pattern (`tree:read`, `tree:*`, `*`), else deny (source `token_scope`).
4. Role grants: tenant membership role; team grants (every team the account
   is in, `Grant{SubjectType:"team"}` on the tree); direct tree grants for the
   user or service account; a service account's own `Role` in its tenant.
   Roles are built-in (§7 matrix, `iam.RoleAllows`) or custom
   (`CustomRole.Permissions`, supporting `area:*`). Visibility (public read
   for everyone, internal read for any authenticated principal) adds
   `tree:read` / `tenant:read`.
5. Enabled policies of the resource tenant: a matching **deny** statement is
   an explicit deny (overrides 4 and every allow). A matching **allow** grants
   the action even without a role.
6. Otherwise allowed iff some role grants the action, else `implicit_deny`.

`branch:push` on a branch resource is allowed iff `tree:write` is allowed and
no deny statement matches `wt:branch/...`. `syncsvc.Push` must evaluate
`branch:push` with the branch (the iam-authz workstream owns that call-site
change). `Decision.Reasons` records every contributing source for the
simulator. Statement matching supports `*` and `**` wildcards (see the domain
comments); conditions are CIDR ranges, MFA, not_before / not_after and a
weekly time window in an IANA timezone.

### 12.2 Authentication additions

`internal/iam.Service` implements `domain.AccountSecurity`.

* Tokens gain `Kind`, `Scopes`, `MFA`, `LastIP`, `UserAgent`. `Authenticate`
  fills `Principal.{Kind,Scopes,MFA,TokenID}`. Service-account keys resolve
  to a service-account principal (`Username "sa:<tenant>/<name>"`, `TenantID`
  = owning tenant, `AccountID ""`).
* MFA: TOTP (RFC 6238, SHA-1, 6 digits, 30 s, one step of skew, replay
  protected via LastUsedStep); 20 random secret bytes, base32;
  `otpauth://totp/W0rkTree:<user>?secret=...&issuer=W0rkTree`; 10 recovery
  codes `xxxx-xxxx`, stored as sha256, single use. Logging in with MFA
  enabled returns `{mfa_required:true, mfa_token}` (valid 5 minutes);
  `/auth/login/mfa` exchanges it plus a TOTP or recovery code for a session.
* Sessions are tokens of Kind session (listing shows id, created, last used,
  last IP, user agent, mfa, current).
* Invitations: 7-day default TTL, one-time code `wti_<base64url>`. Accepting
  adds the membership (and team) for the signed-in account; when the
  invitation names an email or username it must match the accepting account.
* Password resets: admin-issued one-time code `wtr_<base64url>`, 1 h default.

### 13.1 Read/write path security (workstream `sec-paths`)

- `Pull`: compute the paths of the new tip's manifest the caller may not
  read — license rules (`LicenseChecker.CheckRead` per path; the license
  package may expose an optional `UnreadablePaths` helper) and
  `tree:read` path-deny policies (`AccessEvaluator.Evaluate` with
  `Resource.Path`) — return them in `stubbed_paths` (sorted) and leave
  their blobs out of `objects_to_fetch`. Audit `license.denied` (once per
  pull, details: count, first path).
- `pathacl.Checker` implements `domain.PushChecker`: for every changed path
  evaluate `tree:write` with `Resource{Path}`; any explicit deny →
  `PushDenied{Kind:"access_denied", Reason:"writing <path> is denied by
  policy <name>"}`. Register it in `server.go` `PushChecks` (first).
- REST reads (`blob`, `files`, `compare`, file history, snapshot file lists):
  path-denied or license-unreadable paths answer `403 {"code":"path_denied"}`
  / `451 {"code":"license_restricted"}` for content, and are omitted from
  listings (listings add `"restricted_count"`). Blob/content handlers read
  through `content.ReadEntry` (chunked files).
- License rules: `Grantee` (tenant slug; "" = every non-owning tenant) and
  `ExpiresAt` honoured by `CheckPush`/`CheckRead`; validated by the license
  REST handlers; `wt license set --grantee --expires`.
- Owns: `syncsvc/pull.go`, `internal/pathacl`, `internal/license`,
  `httpapi/trees.go`, `httpapi/snapshots.go`, `httpapi/insights.go` (read
  paths only), `crates/worktree-cli/src/commands/license.rs` (flags only).

### 13.2 Chunked large files and shallow sync (workstream `chunks`)

- SDK: files larger than **8 MiB** are stored as FastCDC chunks
  (`scan::chunk_boundaries`, min 256 KiB / avg 1 MiB / max 4 MiB); each
  chunk is a blob; the entry hash names a protobuf `ChunkList` object and
  `chunked = true`. `ObjectStore::read_entry` reassembles; checkout,
  restore, diff, merge, archive, git export, secret scanning and license
  detection all read through it. Push uploads chunk lists and chunks
  (closure expansion), fetch/clone download them, staged uploads include
  them.
- Server: `UploadObjects` accepts `CHUNK_LIST`; `Push` step 5 expands
  chunked entries (chunk list + every chunk must be stored); manifests'
  reachability (`DownloadObjects` scoping, GC) includes chunk lists and
  chunks; `DownloadObjects` **requires** `x-wt-tree-id` for non-admins
  (`FailedPrecondition` otherwise; the SDK always sends it), serves only
  objects reachable from the tree and refuses blobs of paths the caller may
  not read (license `CheckRead` per path); objects are labelled with their
  kind. Max object size stays 64 MiB.
- SDK handles `stubbed_paths`: those files are not written on checkout,
  are listed in `.wt/trees/<tree>/stubbed` and reported by `wt status`
  ("restricted").
- Shallow sync: `wt clone --depth N`, `wt fetch --depth N`, `wt fetch
  --deepen N`, `wt pull --depth N` (uses `PullRequest.depth`). Boundary
  snapshot ids are stored in `.wt/trees/<tree>/shallow`; `wt log` stops
  there (marking "(shallow boundary)"); merge-base searches that hit the
  boundary fail with a clear error suggesting `wt fetch --deepen`.
- Owns: `crates/worktree-sdk/src/{store.rs,scan/cdc.rs,repo/working.rs,
  remote/{push,fetch,clone,stage,client}.rs}`, `syncsvc/objects.go`,
  `syncsvc/push.go` (step 5 only), `commands/sync.rs` (depth flags),
  `commands/status.rs`.

### 13.3 Operations (workstream `ops`)

- Config (flag / env): `--tls-cert/--tls-key` (`WT_TLS_CERT/WT_TLS_KEY`;
  serves HTTPS + gRPC over TLS with ALPN h2), `--tls-client-ca`
  (`WT_TLS_CLIENT_CA`, optional mTLS); a warning is logged when listening
  in cleartext on a non-loopback address. `--gc-interval` (`WT_GC_INTERVAL`,
  default `24h`, `0` disables), `--gc-grace` (`WT_GC_GRACE`, default `720h`),
  `--staged-retention` (`WT_STAGED_RETENTION`, default `168h`, `0` keeps),
  `--audit-retention` (`WT_AUDIT_RETENTION`, default `0` keeps),
  `--rate-limit` (`WT_RATE_LIMIT`, requests per minute per principal or
  anonymous IP, default `1200`, `0` disables), `--default-max-trees`,
  `--default-max-storage` (bytes; `WT_DEFAULT_MAX_TREES`,
  `WT_DEFAULT_MAX_STORAGE`; default `0` = unlimited).
- `gc.Collector`: mark from every branch tip, tag, staged snapshot, MR
  source/target tip and release snapshot/asset (manifests, blobs, chunk
  lists, chunks); unreachable objects are recorded in doc collection
  `gc_marks` (key = hex hash, value `{marked_at}`) and deleted once older
  than the grace period and still unreachable; reachable marked objects are
  unmarked. Also deletes staged snapshots older than the staged retention
  and audit events older than the audit retention (add
  `MetaStore.PruneAudit(ctx, before time.Time) (int, error)`). Runs on the
  interval ticker and on demand. Doc `gc_runs` (key = RFC3339 start) keeps
  the last 20 `GCReport`s.
- `limits.Limiter`: `PushChecker` for tenant quotas (`MaxStorageBytes`
  using doc `tenant_usage` `{bytes}` updated by new objects of accepted
  pushes; `MaxBranchesPerTree` for new branches) → `PushDenied{Kind:
  "quota_exceeded", Reason:"<limit name>"}`; `MaxTrees` and `MaxMembers`
  enforced by the REST tree-create and member-add handlers (409
  `quota_exceeded`). Effective limits = tenant `Limits` overriding server
  defaults. Rate limiting: token bucket per principal (account / service
  account id) or remote IP; HTTP `429 {"code":"rate_limited"}` with
  `Retry-After`, `X-RateLimit-Limit`, `X-RateLimit-Remaining`; gRPC
  `ResourceExhausted` (interceptors in `server.go`). `/healthz` and
  `/metrics` are exempt.
- REST: `POST /admin/gc?dry_run=true|false` → `GCReport`; `GET /admin/gc`
  → `{"config":{...},"runs":[GCReport]}`; `GET|PUT /admin/tenants/{t}/limits`
  (`TenantLimits`); `GET /tenants/{t}/usage` → `{"trees","branches",
  "members","storage_bytes","limits":TenantLimits,"effective":TenantLimits}`;
  `GET /audit` gains `resource_type`, `resource_id`, `until`, action
  prefixes (`iam.*`) and `format=ndjson` (streams every match, no limit;
  `Content-Type: application/x-ndjson`).
- `/healthz`: `{"status":"ok"|"degraded","version","uptime_seconds",
  "checks":{"meta":"ok","objects":"ok"}}`; `503` when a probe fails.
- Metrics: `worktree_sync_pushes_total{result}`, `worktree_sync_pulls_total`,
  `worktree_authz_decisions_total{decision}` (allow/deny, from the HTTP and gRPC
  layers), `worktree_mr_merges_total`, `worktree_gc_runs_total`,
  `worktree_gc_deleted_objects_total`, `worktree_rate_limited_total`.
- Audit completeness: `access.denied` for every 403 answered by the REST
  API and every gRPC `PermissionDenied` (details: method/route, action when
  known); `server.start` / `server.stop` events.
- CLI: `wt admin gc [--dry-run]`, `wt admin gc-status`, `wt admin limits
  <tenant> [--max-trees N] [--max-storage SIZE] [--max-branches N]
  [--max-members N] [--rate N] [--clear]`, `wt admin usage <tenant>`,
  `wt audit --resource-type --resource-id --until --format ndjson`.
- Owns: `internal/{gc,limits,config,audit}`, `server/server.go`
  (TLS, interceptors, tickers), `httpapi/{ops.go,middleware.go,respond.go,
  metrics.go,admin.go}`, `httpapi/httpapi.go` (`handleHealth` only), meta
  audit methods, `commands/{admin,audit}.rs`.

### 13.4 Reviews, CI and linked merges (workstream `review-ci`)

- Approvals record `SnapshotID` = source tip at approval time. Merge counts
  approvals with decision `approved` whose `SnapshotID` equals the current
  source tip (`""` = legacy, counts). A `changes_requested` review from a
  principal with `mr:approve` blocks merging until that principal approves
  the current tip. `POST {tree}/merge-requests/{n}/review`
  `{"decision","body"}` (approve endpoint = decision approved; authors
  cannot approve their own MR; `commented` needs only tree:read).
- Comments: `GET|POST {tree}/merge-requests/{n}/comments`
  `{"body","path?","line?","snapshot_id?"}`, `PATCH|DELETE
  .../comments/{id}` (author, or tree:admin; PATCH may set `resolved`).
  Doc `mr_comments`, key `DocKey(treeID, %08d number, id)`.
- CI: `POST {tree}/ci/status` `{"snapshot","context","state",
  "description?","target_url?"}` requires `ci:report`; `GET
  {tree}/ci/status?snapshot=ID|branch=NAME` → `{"snapshot","state",
  "checks":[CIStatus]}`; combined state = `failure` if any failure/error,
  else `pending` if any pending, else `success` (none → `""`). Doc
  `ci_status`, key `DocKey(treeID, snapshotID, context)`. Event `ci.status`.
- Merge readiness: `GET {tree}/merge-requests/{n}/checks` →
  `{"mergeable","blockers":[{"kind","message"}],"approvals":{"required",
  "current","stale"},"ci":{"state","required":[..],"missing":[..]},
  "todos":{"blocking_open"}}`. Merge enforces: required approvals,
  changes-requested, `RequireCIPass` (every `RequiredChecks` context
  `success` on the source tip; empty list = every reported check),
  `BlockOnTodos` (open blocking TODOs whose `TargetBranch` is the source
  branch in this tree, read from doc collection `todos` §13.5),
  `RequireLinear` (source must be a fast-forward; also enforced for direct
  pushes: merge snapshots rejected). Failures: `409` with
  `{"code":"merge_blocked","message"}`.
- Linked groups: `POST /tenants/{t}/linked-groups` `{"name","members":
  [{"tree":"tenant/tree","number"}]}` (caller needs mr:merge on every
  member tree), `GET /tenants/{t}/linked-groups[/{id}]`, `POST
  .../{id}/merge` (all members must be mergeable; tips are moved with
  compare-and-swap in order and rolled back on failure; event
  `group.merged`), `DELETE .../{id}` closes the group. Members get
  `MergeRequest.LinkedGroup`; merging a member alone → `409
  {"code":"linked_group"}`. Doc `linked_groups`, key `DocKey(tenantID, id)`.
- Tag protections: `GET|PUT|DELETE {tree}/tag-protections` (DELETE
  `?pattern=`), doc `tag_protections` key `DocKey(treeID, pattern)`;
  enforced by `PushTag` (NoMove: existing tags cannot be replaced;
  AllowedTaggers), REST tag create/delete and `DeleteTag` paths.
- CLI: `wt mr review <n> --approve|--request-changes|--comment [-m]`, `wt mr
  comment <n> -m [--path --line]`, `wt mr comments <n>`, `wt mr checks <n>`,
  `wt mr link <name> TREE#N...`, `wt mr merge-group <id>`, `wt mr groups`,
  `wt ci report --snapshot --context --state [--description --url]`, `wt ci
  status [--snapshot|--branch]`, `wt protect set ... --require-ci
  [--check NAME]... --require-signed --require-linear --block-on-todos`,
  `wt protect tag set|list|remove PATTERN [--no-delete --no-move
  --tagger U]`.
- Owns: `internal/{review,ci}`, `httpapi/{mergerequests.go,ci.go,
  reviews.go,manage.go}`, `syncsvc/trees.go` (PushTag/tag paths),
  `commands/{mr,protect,ci}.rs`.

### 13.5 Dependencies, TODOs and releases (workstream `deps-releases`)

- `wt snapshot --depend TREE[@BRANCH] [--depend-tenant T] --todo TITLE

- `todo.Service` subscribes to `branch.pushed`; for each newly pushed

  to a tree whose message contains a line `Completes: #N` (or
  `Completes: tenant/tree#N`) marks that TODO `done` with `ResolvedBy`.
  Doc `todos`, key `DocKey(treeID, %010d number)`; index doc
  `todo_sources`, key `DocKey(sourceSnapshotID, targetTreeID, title)`.
- REST: `GET {tree}/todos?status=&branch=&assignee=` → `{"todos":[Todo]}`,

### 13.6 Snapshot signing (workstream `signing`)

- Keys: Ed25519 (`ed25519-dalek` in Rust, `crypto/ed25519` in Go). Local
  private keys at `<wt home>/keys/<name>.key` (hex seed, mode 0600) and
  `.pub`; `[signing] key = "<name>"`, `auto = true|false`; `wt snapshot
  --sign` signs one snapshot. Signature = Ed25519 over
  `signing::signed_payload` (SnapshotRecord protobuf with `signature`,
  `signing_key_id`, `tree_id`, `branch_name` cleared);
  `SnapshotSignature.key_id` = server key id (stored in the key's `.pub`
  metadata after `wt identity register`; unregistered keys sign with the
  fingerprint as id and the server resolves by fingerprint).
- Server: `GET|POST /auth/keys` (`{"name","public_key":base64}` →
  `SigningKey`), `DELETE /auth/keys/{id}` (revokes), `GET
  /accounts/{username}/keys` (public keys, any authenticated caller).
  Docs `signing_keys` key `DocKey(accountID, id)` and `signing_key_index`
  key = id and = fingerprint → `{account_id,id}`. `signing.Service`
  implements `PushChecker`: every new snapshot carrying a signature must
  verify against an unrevoked registered key (else
  `PushDenied{Kind:"signature_required", Reason:"snapshot X has an invalid
  signature"}`) and is stored with `Verified=true`; on branches whose
  protection has `RequireSigned`, every new snapshot must be verified.
  Audit `snapshot.signature_invalid`.
- CLI: `wt identity generate [NAME] [--force]`, `wt identity list`, `wt
  identity show [NAME]` (fingerprint, public key), `wt identity register
  [NAME]` (uploads, records id), `wt identity revoke ID`, `wt identity

### 13.7 Declarative access and IAM completeness (workstream `access`)

### 14.1 Server-side merges (workstream `server-merge`)

- `internal/merge3`: three-way merge of two `ManifestRecord`s against a
  base (path-level: unchanged/one-side/both-same/both-changed; text
  files merged line-wise with diff3 when both changed; binary, chunked,
  executable-bit and add/add/modify-delete clashes are conflicts). Pure
  functions over an object reader; exhaustive tests.
- `POST {tree}/merge-requests/{n}/merge` body `{"method":"fast-forward|merge|squash","message"?}`.
  Default: fast-forward when possible, else `merge`. `merge` writes a merge
  snapshot (parents `[target tip, source tip]`), `squash` one snapshot
  (parent `[target tip]`) with the combined changes; authored by the merger,
  message default `Merge branch '<src>' into <tgt> (!N)` / the MR title
  for squash. The new objects (merged blobs, manifest) are stored, the
  snapshot is stored with `PushedBy` = merger, the target moves by CAS.
  `BranchProtection.MergeMethods` restricts methods (`409 merge_method_not_allowed`);
  `RequireLinear` forbids `merge`. Conflicts → `409 merge_conflict`
  `{"conflicts":[{"path","kind"}]}`. `GET {tree}/merge-requests/{n}/mergeability`
  → `{"fast_forward":bool,"methods":[...allowed and possible],"conflicts":[...]}`
  (cached per (source tip, target tip)). Linked-group merges accept
  `{"method"}` too. `MergeRequest.MergeMethod` is recorded.
- CLI: `wt mr merge N [TREE] --method fast-forward|merge|squash [-m MSG]`,
  `wt mr mergeability N`, `wt protect set ... --merge-methods a,b`.
- Spec: `specs/server/Merging.md`.
- Owns: `internal/merge3/**`, `internal/review/**`,
  `httpapi/mergerequests.go`, `httpapi/reviews.go`, `commands/{mr,protect}.rs`.

### 14.2 Webhooks (workstream `webhooks`)

- REST (tenant scope needs `tenant:admin`, tree scope `tree:admin`):
  `GET|POST /tenants/{t}/webhooks`, `GET|PATCH|DELETE /tenants/{t}/webhooks/{id}`,
  `GET /tenants/{t}/webhooks/{id}/deliveries?limit=`,
  `GET .../deliveries/{did}`, `POST .../deliveries/{did}/redeliver`,
  `POST /tenants/{t}/webhooks/{id}/test` (sends a `ping` event); the same
  set under `{tree}/webhooks`. Create body `{url, events[], secret?,
  description?, active?}`; the response includes `secret` once when the
  server generated it.
- Delivery: subscribe to the bus; for each matching active hook POST JSON
  `{"id","event","tenant","tree","actor","at","payload"}` with headers
  `Content-Type: application/json`, `User-Agent: W0rkTree-Hookshot/<version>`,
  `X-WT-Event`, `X-WT-Delivery`, `X-WT-Signature: sha256=<hex HMAC-SHA256(secret, body)>`;
  10 s timeout; 2xx = success; retries after 1 m, 5 m, 30 m, 2 h; after 20
  consecutive failed deliveries the hook is deactivated and
  `webhook.failing` is published. Deliveries are kept 30 days / last 200
  per hook. Hooks only see events of their tenant/tree and only events the
  creator could read (re-checked with `tree:read` for tree events).
- SSRF guard: targets resolving to loopback, link-local or private ranges
  are refused unless `--webhook-allow-private` (`WT_WEBHOOK_ALLOW_PRIVATE`,
  add to `internal/config` in a commented block); `http://` targets allowed.
- Audit `webhook.create|update|delete`.
- CLI: `wt webhook list|create|show|update|delete|deliveries|redeliver|test`
  with `--tenant T` or `--tree T/TREE`.
- Spec: `specs/server/Webhooks.md`.
- Owns: `internal/webhooks/**`, `httpapi/webhooks.go`, `commands/webhook.rs`,

### 14.3 Code search (workstream `code-search`)

- `codesearch.Index`: indexes the default-branch tip of every tree
  (trigram index over text files ≤ 1 MiB, skipping binary and chunked
  files), rebuilt incrementally on `branch.pushed` to a default branch and
  `tree.deleted`; built lazily on first query per tree; in memory (index
  metadata in `code_index_meta`).
- `GET /api/v1/search/code?q=&tenant=&tree=&path=&regex=false&case=false&context=2&limit=50`
  → `{"hits":[CodeSearchHit],"truncated":bool,"searched_trees":n}`;
  `q` ≥ 3 characters for literal search; regex uses RE2 with a trigram
  prefilter where possible. Results respect `tree:read`, path-deny policies
  and license `CheckRead`; anonymous callers search public trees only.
  Max 1000 hits; 5 s budget per query.
- CLI: `wt search code QUERY [--tree T/TREE] [--tenant T] [--path GLOB]
  [--regex] [-i] [--context N] [--limit N]` (grep-like output `tree:path:line:text`; `-C` is the global directory flag).
- Spec: `specs/server/CodeSearch.md`.
- Owns: `internal/codesearch/**`, `httpapi/codesearch.go`,

### 14.5 History rewriting and stash (workstream `rewrite`)

- `wt cherry-pick REV... [--no-snapshot] [--continue|--abort]`: applies each
  snapshot's change (vs its first parent) with the three-way merge engine;
  conflicts stop like `wt merge` (same conflict files, `--continue` after
  resolving).
- `wt rebase ONTO [--continue|--abort|--skip]`: replays the current
  branch's first-parent snapshots since the merge base onto ONTO, creating
  new snapshots (new ids, `reverts`/dependencies preserved, signatures
  re-applied if configured), then moves the branch; refuses on pushed
  history unless `--force` (the branch's remote-tracking tip contains the
  rewritten snapshots); reflog entries `rebase`.
- `wt stash [push] [-m MSG] [--include-untracked]`, `list`, `show [N]`,
  `apply [N]`, `pop [N]`, `drop [N]`, `clear`: entries in
  `.wt/trees/<tree>/stash.jsonl` referencing stored manifests; apply is a
  three-way merge onto the working tree.
- `auto_snapshot.on_branch_switch = "stash"`: `wt switch` stashes dirty
  changes with message `auto-stash on <branch>` and, when switching back
  to that branch, pops the newest auto-stash for it.
- SDK modules `repo/rewrite.rs`, `repo/stash.rs` (new), public API on
  `Repository`; GC roots: the stash keeps its manifests reachable (export
  `Repository::stash_roots()` for `wt gc`).
- Spec: `specs/tree/HistoryRewriting.md`.

### 14.6 Storage compression and integrity (workstream `storage`)

- Object encoding, local and server: stored files may be zstd-compressed
  with the 4-byte magic `WTZ1` followed by a zstd frame of the content;
  writers compress when it saves ≥ 10 % and the object is ≥ 512 bytes;
  readers accept raw and compressed files; hashes are always over the
  uncompressed content (unchanged object ids, no migration needed).
  Rust: `zstd` crate in `store.rs`; Go: `github.com/klauspost/compress/zstd`
  in `objstore/disk.go` (server flag `--compress-objects`, default true,
  env `WT_COMPRESS_OBJECTS`). `ObjectSize`/`Size` report stored bytes.
- gRPC message compression: server registers gzip; the SDK client sends
  and accepts gzip for UploadObjects/DownloadObjects.
- `wt gc [--dry-run] [--prune DAYS]`: deletes local objects unreachable from
  branches, tags, remote-tracking refs, reflog entries newer than the prune
  window (default 30 days), stash roots and merge state; reports counts and
  bytes. `wt fsck [--full]`: object hashes, manifests decode, snapshot
  parents and manifests present, refs point at existing snapshots; exit 1
  on errors with a report.
- Server: `POST /api/v1/admin/fsck` (server admin) → `{"objects_checked",
  "corrupt":[hash],"missing":[{snapshot,object}],"duration_ms"}`;
  `wt admin fsck`.
- Spec: `specs/storage/Compression.md` (encoding + gc/fsck).
- Owns: SDK `store.rs`, `remote/client.rs` (compression options only),
  `objstore/**`, `httpapi/fsck.go`, `commands/{gc,fsck,admin}.rs`
  (admin: `fsck` subcommand only), `internal/config` (one flag).

### 15.5 One-step sync and offline queue (workstream `sync`)

- `wt sync [--rebase|--merge] [--no-push] [--all-trees]`: fetch, integrate
  the remote branch (default from config `sync.strategy = "merge"|"rebase"`,
  new key), push; conflicts stop with exit 3 and the usual resolve flow;
  prints a summary.
- Offline queue: when a push fails because the server is unreachable, `wt
  push --queue` (and `wt sync`) record the push in
  `.wt/trees/<tree>/outbox.jsonl`; `wt sync --status`/`wt sync queue`
  lists, `wt sync flush` retries, `wt sync drop N` removes. The daemon
  flushes the queue with backoff when the server becomes reachable
  (`sync.auto_flush = true`), and optionally runs a full `wt sync` every
  `sync.auto_sync_secs` (0 = off) when the working tree is clean.

### 15.6 Git mirrors (workstream `mirrors`)

- `mirror.Service`: per-tree push mirrors to Git remotes. On
  `branch.pushed`/`tag.pushed`/`branch.deleted` (debounced 5 s) and on
  demand, export new snapshots into a bare Git repo under
  `<data>/mirrors/<id>.git` with `git fast-import` (deterministic commits:
  author/committer from the snapshot, message, tree from the manifest,

  persist the snapshot→commit map (`mirror_maps`), then `git push
