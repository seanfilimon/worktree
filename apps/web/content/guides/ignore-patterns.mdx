Because W0rkTree has no staging area, **ignore rules are how you decide what is versioned**: every file in a tree's working directory that is not ignored ends up in the next snapshot. Ignored paths are never snapshotted, never reported by `wt status`, never touched by `wt switch` or `wt restore`, and never watched by the daemon.

## Where patterns come from

| Source | Location | Shared with the team? | Edited with |
|---|---|---|---|
| Built-ins | compiled into `wt` | always active everywhere | (fixed) |
| `.wt/ignore` | inside `.wt/` at the worktree root | **No.** `.wt/` is never snapshotted. | `wt ignore add`, or any editor |
| `.wtignore` | a regular file in the working directory | **Yes.** It is snapshotted and pushed like any other file. | any editor |

`wt ignore list` prints the effective patterns in that order: built-ins, then `.wt/ignore`, then `.wtignore`.

### Built-in ignores

These are always ignored and cannot be un-ignored:

```text
.wt/
.wt-tree/
.git/
target/
node_modules/
.DS_Store
*.swp
```

`.wt/` and `.wt-tree/` are W0rkTree's own metadata and nested-tree markers. `.git/` means a Git repository in the same directory is never captured, which is convenient while migrating.

### `.wt/ignore` vs `.wtignore`

- Use **`.wtignore`** for project rules everyone needs (build output, caches, generated code). Commit it with a snapshot so clones get it.
- Use **`.wt/ignore`** for rules that only apply to your machine (editor folders, personal scratch files). `wt ignore add` writes here.
- `wt git import` converts `.gitignore` into `.wt/ignore`. Copy the rules into `.wtignore` if your team should share them (see [Migration](/guides/migration)).

## Pattern syntax

Patterns use gitignore syntax, one per line:

| Pattern | Matches |
|---|---|
| `# comment` | Nothing; blank lines are ignored too. |
| `*.log` | Any file named `*.log` in any directory (a pattern without `/` matches the file name at any depth). |
| `dist/` | A trailing `/` restricts the pattern to directories: `dist` and everything below it. |
| `docs/build/` | A pattern containing `/` is matched against the whole path from the root. |
| `*` | Any run of characters except `/`. |
| `?` | Any single character except `/`. |
| `**` | Any number of directories: `src/**/*.gen.rs` matches `src/a.gen.rs` and `src/x/y/b.gen.rs`. |
| `!important.log` | Negation: re-include a path that an earlier pattern ignored. |

The **last** matching pattern wins, so put negations after the patterns they override:

```text
*.log
!release-notes.log
```

Paths are `/`-separated and relative to the worktree root on every platform, including Windows.

## `wt ignore`

```text
wt ignore list | add PATTERN | check PATH
```

<Tab value="bash">

```bash
wt ignore list
wt ignore add "*.log"
wt ignore add ".idea/"
wt ignore check build/output.log
wt ignore check src/main.rs
```

</Tab>
<Tab value="PowerShell">


Quote patterns so your shell does not expand `*` itself. `wt ignore check PATH` reports whether a path relative to the worktree root is ignored; use it to debug a rule before snapshotting.

## A typical `.wtignore`

```text
# build output
dist/
build/
coverage/

# caches and environments
.cache/
__pycache__/
*.pyc
.venv/

# local configuration that may hold secrets
.env
.env.*
!.env.example

# logs
*.log
```

`target/` and `node_modules/` are already built-in, so they do not need to be listed.

<Callout type="info" title="Ignore rules and secrets">
Ignoring `.env` and similar files keeps them out of snapshots entirely. The [secret scan](/docs/cli/snapshots#secret-scan) is the safety net for anything that slips through: it runs on added and modified files before every snapshot and refuses the snapshot when it finds credentials.
</Callout>

## Ignoring files that are already versioned

Adding a pattern does not remove a file from snapshots that already contain it. Once the pattern is in place, the path is no longer part of the tree's working state, so the **next** snapshot no longer contains it, while older snapshots keep it (history is append-only).

```bash
wt ignore add "secrets.local.toml"
wt status                 # check what the next snapshot will drop
wt snapshot -m "Stop versioning secrets.local.toml"
```

If the file contained a real secret, rotate the secret: it remains readable in earlier snapshots, locally and on the server if they were pushed.

## Ignore rules and nested trees

Ignore rules apply to the whole worktree, including nested trees. In addition, each nested tree's directory is automatically excluded from its parent tree, so you never need ignore patterns to separate trees. See [Nested trees](/guides/nested-trees).

## Ignore rules and the daemon

The daemon ignores file events for ignored paths and under `.wt/`, so build output does not trigger auto-snapshots. If the daemon snapshots more often than you expect, look for a busy directory that should be ignored with `wt daemon status` (pending changes) and `wt ignore check`.
