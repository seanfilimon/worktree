This guide moves an existing Git repository to W0rkTree v0.2.0. The Git bridge (`wt git import` / `wt git export`) copies history in both directions, so you can migrate gradually and keep Git consumers working while the team switches.

## Concept mapping

| Git | W0rkTree | Notes |
|---|---|---|
| repository | worktree (`.wt/`) with a root tree | A worktree can also contain [nested trees](/guides/nested-trees). |
| commit | snapshot | Immutable; UUID v4 id instead of a SHA-1. |
| staging area / index | none | `wt snapshot` captures the whole working tree of the selected tree. There is no `add` step. |
| branch | branch | Per tree. Branches are archived (`wt branch archive`), never hard-deleted, and can be restored. |
| tag | tag | `wt tag create NAME [REV] [-m MSG]`; pushed by `wt push`. |
| remote | remote | A server URL **plus a tenant**: `wt remote add origin URL --tenant T`. |
| `clone` / `fetch` / `push` / `pull` | `wt clone` / `wt fetch` / `wt push` / `wt pull` | `wt clone URL TENANT/TREE [DEST]`. No force push exists. |
| `reset --hard` | `wt restore` or `wt revert` | `wt restore` discards working changes; moving a branch backwards is not possible, so undo with `wt revert`, which adds a new snapshot. |
| `rebase`, `commit --amend` | none | History is append-only. |
| `stash` | none | Work on a feature branch and snapshot unfinished work there (snapshots are cheap and the daemon takes them automatically), or share it with `wt stage`. |
| submodules | nested trees | Independently versioned directories inside one worktree (`wt tree add`). |
| `.gitignore` | `.wtignore` and `.wt/ignore` | Same gitignore syntax. |
| reflog | reflog | `wt reflog`, per tree, append-only. |
| hooks, CI integration | `pre-snapshot` / `post-snapshot` hooks, `wt ci` | Secret scanning is built into `wt snapshot`; CI systems report checks with `wt ci report`, and branch protection can require them. |

The biggest habit change: there is no index. Whatever is in the tree's working directory (minus ignored paths) is what the next snapshot records. Keep generated files out with ignore rules rather than by not staging them.

## Before you import

- **Check out every branch you need as a local branch.** The import reads local branches only; remote-tracking branches such as `origin/release-1.x` are skipped.

  ```bash
  git -C ~/src/app branch --track release-1.x origin/release-1.x
  ```

- **Commit or discard local changes.** Uncommitted work, stashes and the Git index are not imported.
- **Check for Git LFS and submodules.** LFS files arrive as their small pointer files, and submodules are not converted into nested trees (see [What does not migrate](#what-does-not-migrate)).
- **Look for committed secrets.** The import copies history as-is; the secret scan runs on your next `wt snapshot`, not on imported history.

## Step by step

<Steps>
<Step>

### Import the repository

```text
wt git import GIT_PATH [DEST]
```

<Tabs items={['bash', 'PowerShell']}>
<Tab value="bash">

```bash
wt git import ~/src/app ./app
cd app
```

</Tab>
<Tab value="PowerShell">

```powershell
wt git import C:\src\app .\app
cd .\app
```

</Tab>
</Tabs>

Every local branch's commit graph becomes snapshots on the **root tree** (parents, author, timestamp and message preserved; merge commits become two-parent snapshots), lightweight and annotated tags become tags, `.gitignore` is converted into `.wt/ignore`, and one branch is checked out. The worktree, and therefore its root tree, is named after `DEST`.

</Step>
<Step>

### Verify the history

```bash
wt log -n 20 --oneline
wt branch
wt tag
wt status
wt ignore list
```

`wt status` should be clean. Compare a few files or whole revisions with the Git repository; `wt diff` works between any two revisions, for example `wt diff v1.0.0 main --stat`.

</Step>
<Step>

### Make ignore rules shareable

`.wt/ignore` lives inside `.wt/` and is never snapshotted, so clones would not get it. To share the rules, copy them into a `.wtignore` file in the working directory and snapshot it:

<Tabs items={['bash', 'PowerShell']}>
<Tab value="bash">

```bash
cp .gitignore .wtignore
wt snapshot -m "Add .wtignore"
```

</Tab>
<Tab value="PowerShell">

```powershell
Copy-Item .gitignore .wtignore
wt snapshot -m "Add .wtignore"
```

</Tab>
</Tabs>

See [Ignore patterns](/guides/ignore-patterns).

</Step>
<Step>

### Push to a server

Log in, add a remote for the tenant that will own the tree, and push each branch. `wt push` pushes one branch at a time (default: the current one) and uploads local tags the server does not have.

```bash
wt login https://wt.example.com -u alice
wt remote add origin https://wt.example.com --tenant acme
wt push --branch main
wt push --branch release-1.x
```

The first push creates the server tree `acme/app`. For an organization tenant you need a developer role or higher in it (`tree:write`). Tenants and memberships are managed through the [REST API](/docs/server/rest-api) or the [admin panel](/guides/admin-panel); see [Multi-tenancy](/guides/multi-tenancy).

</Step>
<Step>

### Roll it out to the team

1. Add teammates to the tenant with the right roles (`owner`, `admin`, `maintainer`, `developer`, `viewer`).
2. Protect `main` and other release branches with [branch protection](/guides/branch-protection) rules if you want reviewed merges.
3. Freeze the Git repository (make it read-only) at a fixed point, or keep exporting to it during a transition (below).
4. Each teammate clones: `wt clone https://wt.example.com acme/app`.
5. Optionally, everyone runs the daemon for auto-snapshots and team-visible WIP: `wt daemon start` and `wt daemon watch`. See [Auto-tracking setup](/guides/auto-tracking-setup).

</Step>
</Steps>

## Round-trip back to Git

`wt git export` writes snapshots back into a Git repository as commits with the same parents, author, timestamp and message. The snapshot-to-commit mapping is kept in `.wt/git-map.json`, so repeated exports are incremental and deterministic.

```bash
wt git export ../app-git               # all branches of the root tree
wt git export ../app-git --rev main    # one revision
git -C ../app-git remote add origin git@git.example.com:acme/app.git   # once
git -C ../app-git push origin --all --follow-tags                     # publish with Git itself
```

Use this to keep a Git mirror for tools that only speak Git, or as an exit path. Details and workflows are in [Git interop](/guides/git-interop).

## What does not migrate

| Git feature | In v0.2.0 |
|---|---|
| Remote-tracking branches | Not imported. Create local branches first. |
| Uncommitted changes, stashes, the index | Not imported. |
| Hooks and `.git/config` | Not imported. W0rkTree has its own `pre-snapshot` / `post-snapshot` hooks; see [Hooks](/docs/cli/configuration#hooks). |
| Git reflog | Not imported. The W0rkTree reflog starts at the import. |
| Submodules | Not converted into nested trees. Set nested trees up afterwards with `wt tree add`. |
| Git LFS | `.gitattributes` filters are not applied, so LFS-tracked files arrive as pointer files. Fetch the real content in Git (`git lfs checkout`) and snapshot it, or keep large binaries out of the tree. |
| Commit and tag signatures | Not preserved. Sign new snapshots with W0rkTree's own Ed25519 keys; see [Snapshot signing](/docs/cli/signing). |
| Committer (as distinct from author) | Only author, timestamp and message are carried over. |
| Commit SHAs | Snapshots get new UUID ids; correlate through `.wt/git-map.json` after an export. |

<Callout type="warn" title="Roadmap">
A live Git mirror mode and automatic submodule-to-nested-tree conversion are not built yet. See the [roadmap](/roadmap).
</Callout>

## Command cheat sheet

| Git | W0rkTree |
|---|---|
| `git init` | `wt init` |
| `git status` | `wt status` |
| `git add -A && git commit -m "msg"` | `wt snapshot -m "msg"` |
| `git commit --allow-empty -m "msg"` | `wt snapshot -m "msg" --allow-empty` |
| `git log --oneline -n 10` | `wt log --oneline -n 10` |
| `git show <rev> --stat` | `wt show <rev> --stat` |
| `git diff`, `git diff a b --stat` | `wt diff`, `wt diff a b --stat` |
| `git branch` / `git branch -a` | `wt branch` / `wt branch -a` (`-a` includes archived) |
| `git branch new` | `wt branch create new` |
| `git switch new` / `git switch -c new` | `wt switch new` / `wt switch -c new` |
| `git branch -d old` | `wt branch archive old` (restore with `wt branch restore old`) |
| `git merge feature`, `--no-ff` | `wt merge feature`, `--no-ff` |
| `git merge --continue` / `--abort` | `wt merge --continue` / `wt merge --abort` |
| `git revert <rev>` | `wt revert <rev>` |
| `git restore <file>` / `git checkout -- <file>` | `wt restore <file>` |
| `git restore --source v1.0 docs/` | `wt restore docs/ --from v1.0` |
| `git tag -a v1.0 -m "msg"` | `wt tag create v1.0 -m "msg"` |
| `git tag -d v1.0` | `wt tag delete v1.0` (local only) |
| `git push --tags` | included in `wt push` |
| `git remote add origin URL` | `wt remote add origin URL --tenant T` |
| `git clone URL` | `wt clone URL TENANT/TREE [DEST]` |
| `git fetch` / `git pull` / `git push` | `wt fetch` / `wt pull` / `wt push` |
| `git push --force` | not possible; `wt pull`, then `wt push` |
| `git reflog` | `wt reflog` |
| `git archive -o out.zip HEAD` | `wt archive HEAD -o out.zip --format zip` |
| `git config user.name "Name"` | `wt config set user.name "Name"` |
| `git check-ignore -v path` | `wt ignore check path` |
| `git submodule add URL path` | `wt tree add NAME path` |
| `git stash` / `git stash pop` | `wt stash` / `wt stash pop` (or `auto_snapshot.on_branch_switch = "stash"` to stash automatically on `wt switch`) |
| `git rebase main` / `git cherry-pick X` | `wt rebase main` / `wt cherry-pick X` (unpushed history only, unless `--force`) |
