Trees often mix code with different licenses: your own proprietary code, a vendored MIT library, a GPL tool. W0rkTree lets a tree's owners record that per path with **license rules**, and the server enforces them for callers outside the owning tenant.

## License rules

A `LicenseRule` assigns an SPDX license and a **grant** to every path matching a glob:

| Field | Meaning |
|---|---|
| `path_glob` | `**`-style glob with `/` separators, for example `vendor/**`, `third_party/zlib/**`, or `**/*.proto`. One rule per glob per tree. |
| `spdx` | SPDX license identifier, for example `MIT`, `Apache-2.0`, `GPL-3.0-only`, or `LicenseRef-Proprietary`. |
| `grant` | What non-owning tenants may do with matching paths: `read-only`, `modify`, or `redistribute`. |

The response objects also carry `tree_id`.

### Grants

| Grant | Read | Push changes | Export / redistribute |
|---|---|---|---|
| `read-only` | Yes | No | No |
| `modify` | Yes | Yes | No |
| `redistribute` | Yes | Yes | Yes |

Rules restrict **non-owning tenants** only. The tenant that owns the tree is not limited by its own license rules.

## How the server enforces rules

- **Pushes.** For every push, the server computes the changed paths and asks the license checker whether the pusher's tenant may write them. If a changed path is covered by a rule whose grant does not allow modification, the whole push is rejected with `license_violation`, naming the offending `path` and its `license`.
- **Reads and exports.** When a caller from another tenant reads or exports covered paths, the server checks the grant and refuses with `license_violation` if the paths may not be read or exported by that caller.

Other checks still apply first: a caller needs read access to the tree at all (see [tree visibility](/guides/multi-tenancy#tree-visibility)) and `tree:write` to push. License rules narrow what is allowed; they never grant access on their own.

A rejected push looks like any other push rejection: `wt push` exits with code 1 and prints the reason, here the path and license. Nothing from the rejected push becomes part of the branch. See [Branch Protection](/guides/branch-protection#push-rejections) for the other rejection kinds.

## Set up rules

Managing license rules requires `tree:admin` on the tree (tenant `admin` or `owner`).

<Steps>
<Step>

### Inventory your licenses

List the third-party directories in the tree and the license of each. Rules are matched by glob, so group paths by directory where you can.

</Step>
<Step>

### Create the rules

<Tabs items={['bash', 'PowerShell']}>
<Tab value="bash">

```bash
curl -s -X PUT http://localhost:7420/api/v1/trees/acme/app/licenses \
  -H "Authorization: Bearer $WT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"path_glob":"vendor/zlib/**","spdx":"Zlib","grant":"redistribute"}'

curl -s -X PUT http://localhost:7420/api/v1/trees/acme/app/licenses \
  -H "Authorization: Bearer $WT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"path_glob":"engine/**","spdx":"LicenseRef-Proprietary","grant":"read-only"}'
```

</Tab>
<Tab value="PowerShell">

```powershell
$headers = @{ Authorization = "Bearer $env:WT_TOKEN" }
$uri = "http://localhost:7420/api/v1/trees/acme/app/licenses"

Invoke-RestMethod -Method Put -Headers $headers -ContentType "application/json" -Uri $uri `
  -Body '{"path_glob":"vendor/zlib/**","spdx":"Zlib","grant":"redistribute"}'

Invoke-RestMethod -Method Put -Headers $headers -ContentType "application/json" -Uri $uri `
  -Body '{"path_glob":"engine/**","spdx":"LicenseRef-Proprietary","grant":"read-only"}'
```

</Tab>
</Tabs>

`PUT` creates the rule for that `path_glob`, or replaces it if one exists.

</Step>
<Step>

### Review and prune

```text
GET    /api/v1/trees/{tenant}/{tree}/licenses              list rules
DELETE /api/v1/trees/{tenant}/{tree}/licenses?path_glob=   remove the rule for one glob
```

URL-encode the glob when deleting, for example `?path_glob=vendor%2Fzlib%2F%2A%2A`.

</Step>
</Steps>

In the admin panel, open **Trees**, select the tree, and manage its license rules from the tree detail page. See the [Admin Panel guide](/guides/admin-panel).

## Detecting licenses with the SDK

The Rust SDK includes a helper that recognizes an SPDX id from a `LICENSE` file body or an `SPDX-License-Identifier:` header:

```rust
use worktree_sdk::scan::detect_license;

let body = std::fs::read("vendor/zlib/LICENSE")?;
if let Some(id) = detect_license(&body) {
    println!("vendor/zlib/** -> {id}");
}
```

It returns `None` when the license is not recognized. It is a library function for building your own tooling, such as a script that proposes rules for each vendored directory. It does not create rules by itself, and `wt` does not call it for you.

## Tips

- **Prefer directory globs.** `vendor/foo/**` is easier to audit than many per-file rules.
- **Use `LicenseRef-` ids** for licenses that have no SPDX identifier, such as internal proprietary terms.
- **Keep rules next to the code they describe.** When you add or move a vendored directory, update its rule in the same change window.

<Callout type="warn" title="Roadmap">
  License rules can also be managed with [`wt license`](/docs/cli/administration#wt-license) (`list`, `set`, `remove`, `detect`).
</Callout>
