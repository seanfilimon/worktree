**W0rkTree** is a version control system designed as a replacement for Git. It keeps history as immutable **snapshots**, splits a project into independently versioned **nested trees**, shares work in progress with the team as **staged snapshots** before anything is pushed, and syncs with a **multi-tenant server** that enforces access control, branch protection, and license rules.

<Callout type="info" title='v0.2.0 ("v2 rebuild")'>
  This documentation covers **v0.2.0**, a pre-1.0 release. Commands, APIs, and on-disk formats may still change before 1.0. There are no prebuilt binaries or package-manager installs yet: you [build W0rkTree from source](/docs/installation).
</Callout>

## Core ideas

- **Snapshots, not commits.** A snapshot is an immutable record of a tree's complete file listing (a manifest of BLAKE3-addressed blobs) plus its parents, author, and message. History is append-only: `wt revert` adds a new snapshot, branches are archived rather than deleted, and the server has no force push.
- **Nested trees.** One worktree can contain several trees. Each tree has its own branches, tags, reflog, and server-side name, and a tree's snapshots exclude the paths of trees nested inside it. See [Nested trees](/guides/nested-trees).
- **Staged, team-visible WIP.** `wt stage` (or the background daemon, automatically) uploads your current working state as a staged snapshot. Teammates see it with `wt status --team` without it ever entering branch history. See [Staged visibility](/guides/staged-visibility).
- **Automatic local history.** The background daemon `worktree-bg` watches your worktree and takes auto-snapshots after a period of inactivity, so work is never lost between explicit snapshots.
- **Multi-tenant server.** Accounts, personal and organization tenants, roles, tree visibility, branch protection with merge requests, per-path license rules, an audit log, and live Server-Sent Events, all on a single port.
- **Secret scanning.** Every `wt snapshot` scans added and modified files for credentials before anything is recorded. See [Security](/docs/security).

## Architecture

```text
 wt (CLI, Rust) ──► worktree-sdk (Rust) ──► .wt/ on disk
      │                  │  remote (gRPC h2c + REST)
      │ ipc (JSON/TCP)   ▼
 worktree-bg (Rust) ──► worktree-server (Go, services/server-go) ──► bbolt meta + CAS objects
                              ▲ REST + SSE
                        apps/admin (React/Vite admin panel)
 worktree-git (Rust) — Git import/export over worktree-sdk
 apps/web (Next.js) — marketing + docs site
```

The CLI and the daemon are thin layers over the Rust SDK, which owns everything inside `.wt/`. The SDK talks to the server over gRPC (cleartext HTTP/2, h2c) for sync and over REST for authentication. The server serves gRPC, REST, SSE, and the static admin panel on **one port**, `7420` by default, so a remote URL is simply `http://localhost:7420`.

## Components

| Component | Location | Role |
|---|---|---|
| `wt` CLI | `crates/worktree-cli` | The command-line client. Every local and remote operation. See [CLI reference](/docs/cli). |
| `worktree-sdk` | `crates/worktree-sdk` | The local engine: object store, snapshots, branches, merge, diff, secret scan, server client, daemon IPC. See [Rust SDK](/docs/sdk). |
| `worktree-bg` | `crates/worktree-bg` | Background daemon: file watching, auto-snapshots, auto-staging. Normally started with [`wt daemon start`](/docs/cli/daemon#wt-daemon). |
| `worktree-git` | `crates/worktree-git` | Git import/export bridge used by [`wt git`](/docs/cli/git). |
| `worktree-protocol` | `crates/worktree-protocol` | Shared types and the gRPC contract `proto/sync.proto` (package `worktree.sync.v1`). See [Protocol](/docs/protocol). |
| Go server | `services/server-go` | `worktree-server`: canonical history, IAM, policy, REST API, events. See [Server](/docs/server). |
| Admin panel | `apps/admin` | React + Vite web UI over the REST API, served by the server at `/admin/`. See [Admin panel](/guides/admin-panel). |
| Website | `apps/web` | This site: marketing pages and documentation (Next.js + Fumadocs). |

## A first session

```bash
wt init my-project && cd my-project
wt snapshot -m "First snapshot"
wt remote add origin http://localhost:7420 --tenant ada
wt login
wt push
```

The [Quick start](/guides/quick-start) walks through this end to end, including running a local server.
