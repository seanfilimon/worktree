The CLI controls the background daemon `worktree-bg` through a small JSON protocol defined in `worktree_sdk::ipc` (`crates/worktree-sdk/src/ipc.rs`). [`wt daemon`](/docs/cli/daemon#wt-daemon) subcommands are thin wrappers around it, and any tool running as the same user can use it to inspect or drive the daemon. The [BgProcess specification](https://github.com/seanfilimon/worktree/blob/main/crates/worktree-protocol/specs/bgprocess/BgProcess.md) (§9) is normative.

## Transport

- **Newline-delimited JSON over TCP** on `127.0.0.1` only.
- **One request line, one response line per connection.** The client connects, writes one JSON object followed by `\n`, reads one JSON line back, and closes. Lines are limited to 1 MiB (`MAX_LINE_BYTES`).
- **Token.** Every request carries the daemon's random `token` as a top-level `"token"` field next to `"cmd"`. Requests with a missing or wrong token get an `error` response starting with `unauthorized` and have no effect.
- **Timeouts.** 5 s to connect, send and receive quick responses (`IPC_TIMEOUT`); 300 s for `watch`, `snapshot_now` and `prepare_switch` (`IPC_SLOW_TIMEOUT`).
- The port is chosen by the daemon (an ephemeral port) and published in `bg.json`.

## Discovery: `bg.json`

On startup the daemon writes `$WT_HOME/bg.json` (default `~/.wt/bg.json`, `%USERPROFILE%\.wt\bg.json` on Windows) and removes it on clean shutdown:

```json
{"pid": 4242, "port": 51873, "version": "0.1.0", "token": "6f1c...e9a2"}
```

| Field | Type | Meaning |
|---|---|---|
| `pid` | `u32` | Daemon process id. |
| `port` | `u16` | Loopback TCP port to connect to. |
| `version` | string | Daemon version. |
| `token` | string | Secret every request must carry. Regenerated by each daemon instance. Empty in files written by older daemons, which must be restarted. |

```rust
pub struct DaemonInfo { pub pid: u32, pub port: u16, pub version: String, pub token: String }

pub fn daemon_info_path() -> PathBuf                     // $WT_HOME/bg.json
pub fn read_daemon_info() -> Result<Option<DaemonInfo>>  // does not check liveness
pub async fn send(req: &IpcRequest) -> Result<IpcResponse>
pub async fn send_to(port: u16, token: &str, req: &IpcRequest) -> Result<IpcResponse>
```

`send` reads `bg.json`, connects, and exchanges one request and response with the token attached. It returns `SdkError::DaemonNotRunning` if `bg.json` is missing or the connection is refused (a stale file left by a crash). The server side is `ipc::serve(listener, token, handler, shutdown)`, which checks the token (in constant time) before calling the handler.

## Requests

`IpcRequest` is tagged by a `cmd` field (snake_case):

| Variant | JSON (token omitted) | Effect |
|---|---|---|
| `Status` | `{"cmd":"status"}` | Return a `DaemonStatus`. |
| `Watch { path }` | `{"cmd":"watch","path":"/home/ada/src/my-project"}` | Start watching the worktree containing `path`. Persisted to `bg.toml`. |
| `Unwatch { path }` | `{"cmd":"unwatch","path":"/home/ada/src/my-project"}` | Stop watching a worktree. Persisted to `bg.toml`. |
| `Pause { path }` | `{"cmd":"pause","path":null}` | Pause auto-snapshots for one worktree, or all when `path` is null. |
| `Resume { path }` | `{"cmd":"resume","path":"/home/ada/src/my-project"}` | Resume auto-snapshots for one worktree, or all when `path` is null. |
| `SnapshotNow { path }` | `{"cmd":"snapshot_now","path":"/home/ada/src/my-project"}` | Snapshot (and stage) every changed tree of the worktree now, ignoring pause and `enabled`. |
| `PrepareSwitch { path, tree }` | `{"cmd":"prepare_switch","path":"/home/ada/src/my-project","tree":"web"}` | Sent by `wt switch` before switching: snapshots `tree` first when `auto_snapshot.on_branch_switch = "snapshot"` and auto-snapshots are not paused or disabled. |
| `Shutdown` | `{"cmd":"shutdown"}` | Stop the daemon (it takes a final auto-snapshot of pending changes first). |

Paths must be absolute. On Windows they are ordinary Windows paths with escaped backslashes, for example `"C:\\Users\\ada\\src\\my-project"`. `ipc::prepare_branch_switch(root, tree)` is the best-effort client helper the CLI uses; it returns `None` when no daemon runs or the daemon declines.

## Responses

`IpcResponse` is tagged by a `result` field (snake_case):

| Variant | JSON |
|---|---|
| `Status(DaemonStatus)` | `{"result":"status", ...DaemonStatus fields}` |
| `Ok { message }` | `{"result":"ok","message":"..."}` |
| `Error { message }` | `{"result":"error","message":"..."}` |

### `DaemonStatus`

| Field | Type | Meaning |
|---|---|---|
| `pid` | `u32` | Daemon process id. |
| `version` | string | Daemon version. |
| `started_at` | timestamp | When the daemon started (RFC 3339, UTC). |
| `watched` | `WatchedWorktree[]` | One entry per watched worktree. |

### `WatchedWorktree`

| Field | Type | Meaning |
|---|---|---|
| `root` | path | Worktree root. |
| `paused` | bool | Whether auto-snapshots are paused. |
| `pending_changes` | integer | Changed files waiting for the next auto-snapshot. |
| `snapshots_created` | integer | Auto-snapshots taken since the daemon started. |
| `last_snapshot` | string or null | Id of the last auto-snapshot. |
| `last_snapshot_at` | timestamp or null | When it was taken. |
| `last_stage_at` | timestamp or null | When work was last uploaded as a staged snapshot. |
| `last_error` | string or null | Most recent snapshot or stage error, for example a secret-scan finding or a failing hook. |
| `last_fetch_at` | timestamp or null | When the background sync loop last fetched remote branches. |
| `sync_state` | string or null | Sync loop state, for example `watching`, `polling`, `offline` or `disabled`. |
| `sync_error` | string or null | The last sync failure, cleared by the next successful fetch. |

Example status response (illustrative values):

```json
{
  "result": "status",
  "pid": 4242,
  "version": "0.1.0",
  "started_at": "2026-10-25T09:00:00Z",
  "watched": [
    {
      "root": "/home/ada/src/my-project",
      "paused": false,
      "pending_changes": 3,
      "snapshots_created": 12,
      "last_snapshot": "9b1f3c2e-...",
      "last_snapshot_at": "2026-10-25T10:41:07Z",
      "last_stage_at": "2026-10-25T10:41:08Z",
      "last_error": null,
      "last_fetch_at": "2026-10-25T10:42:00Z",
      "sync_state": "watching",
      "sync_error": null
    }
  ]
}
```

## Talking to the daemon by hand

Include the token from `bg.json` in the request line:

<Tabs items={['bash', 'PowerShell']}>
<Tab value="bash">

```bash
INFO="${WT_HOME:-$HOME/.wt}/bg.json"
PORT=$(jq -r .port "$INFO")
TOKEN=$(jq -r .token "$INFO")
printf '{"cmd":"status","token":"%s"}\n' "$TOKEN" | nc 127.0.0.1 "$PORT"
```

</Tab>
<Tab value="PowerShell">

```powershell
$wtHome = if ($env:WT_HOME) { $env:WT_HOME } else { Join-Path $env:USERPROFILE '.wt' }
$info = Get-Content (Join-Path $wtHome 'bg.json') | ConvertFrom-Json
$client = [System.Net.Sockets.TcpClient]::new('127.0.0.1', $info.port)
$stream = $client.GetStream()
$writer = [System.IO.StreamWriter]::new($stream); $writer.AutoFlush = $true
$writer.WriteLine((@{ cmd = 'status'; token = $info.token } | ConvertTo-Json -Compress))
[System.IO.StreamReader]::new($stream).ReadLine()
$client.Close()
```

</Tab>
</Tabs>

From Rust, `send` attaches the token for you:

```rust
use worktree_sdk::ipc::{self, IpcRequest, IpcResponse};

#[tokio::main]
async fn main() -> worktree_sdk::Result<()> {
    match ipc::send(&IpcRequest::Status).await? {
        IpcResponse::Status(status) => {
            for w in status.watched {
                println!("{} paused={} pending={} sync={:?}",
                    w.root.display(), w.paused, w.pending_changes, w.sync_state);
            }
        }
        IpcResponse::Ok { message } => println!("{message}"),
        IpcResponse::Error { message } => eprintln!("daemon error: {message}"),
    }
    Ok(())
}
```

<Callout type="info" title="Security">
  The daemon listens on loopback only, and only processes that can read `bg.json` (your own) know the token, although other local users can reach the port. Keep `$WT_HOME` readable only by you. IPC messages never carry server tokens: the daemon reads `$WT_HOME/credentials.toml` itself when it stages or fetches.
</Callout>
