import { Callout } from 'fumadocs-ui/components/callout';

`worktree_sdk::remote` is the client for the W0rkTree server. It speaks the gRPC `worktree.sync.v1.SyncService` over h2c and the REST auth endpoints, both on the same base URL (for example `http://localhost:7420`). The `wt` remote commands and the daemon's auto-staging are built on these functions. The wire-level flows are described in [Sync protocol](/docs/protocol/sync-protocol).

All network functions are `async` (Tokio) and return `worktree_sdk::Result<T>`. Functions that take a `remote` name look up `[remote.<name>]` (`url`, `tenant`) in the worktree's `config.toml` (`RemoteNotConfigured` if missing) and use the saved credential for that URL.

## Credentials

```rust
pub struct Credential {
    pub username: String,
    pub token: String,
}

pub fn load_credential(server: &str) -> Result<Option<Credential>>
pub fn save_credential(server: &str, cred: &Credential) -> Result<()>
pub fn remove_credential(server: &str) -> Result<()>
```

Credentials live in `$WT_HOME/credentials.toml`, keyed by the normalized server URL (no trailing slash). These functions are synchronous. `wt logout` calls `remove_credential`. When no credential exists, remote calls are made anonymously, which the server allows only for `Ping` and reads of public trees; operations that need an identity fail with `NotLoggedIn`.

<Callout type="warn">
  The token is a bearer credential stored in plain text. Keep `$WT_HOME` private; in tests, point `WT_HOME` at a temporary directory. See [Security](/docs/security#local-credential-file).
</Callout>

## Login and registration

```rust
pub struct LoginInfo {
    pub server: String,
    pub username: String,
    pub account_id: String,
    pub tenant: String,
    pub token: String,
}

pub async fn login(server: &str, username: &str, password: &str) -> Result<LoginInfo>
pub async fn register(server: &str, username: &str, email: &str, password: &str) -> Result<LoginInfo>
```

| Function | Behavior |
|---|---|
| `login` | `POST /api/v1/auth/login`; saves the credential on success. The returned session token lasts 30 days by default. |
| `register` | `POST /api/v1/auth/register`; creates the account and its personal tenant (slug = username) and saves the credential. Fails if the server has registration disabled. |

`tenant` is the account's personal tenant slug.

## Ping

```rust
pub struct PingInfo {
    pub server_version: String,
    pub username: Option<String>,
    pub tenant: Option<String>,
}

pub async fn ping(server: &str) -> Result<PingInfo>
```

gRPC `Ping` with the saved credential, if any. `username` and `tenant` are `None` when the call is anonymous or the token is invalid. Used by `wt whoami`.

## Push

```rust
pub struct PushReport {
    pub tree: String,
    pub branch: String,
    pub old_tip: Option<String>,
    pub new_tip: String,
    pub snapshots_sent: usize,
    pub objects_sent: usize,
    pub up_to_date: bool,
}

pub async fn push(repo: &Repository, tree: &str, remote: &str, branch: Option<&str>) -> Result<PushReport>
```

Pushes `branch` (default: the current branch) of `tree` to `remote`:

1. `ResolveTree` with `create_if_missing`.
2. Pull-style negotiation of the snapshots the server is missing.
3. `UploadObjects` for missing manifests and blobs.
4. `Push` with `old_tip` set to the last known remote tip.

A `PushRejection` from the server maps to `SdkError::PushRejected` (the message names the reason, such as a conflict with the server tip, branch protection, or a license violation). On success it updates `refs/remotes/<remote>/<branch>` and also pushes local tags that are not on the server. `up_to_date` is true when there was nothing to send.

## Fetch

```rust
pub struct FetchReport {
    pub tree: String,
    /// (branch, old remote tip, new remote tip) for every changed branch.
    pub updated: Vec<(String, Option<String>, Option<String>)>,
    pub snapshots_received: usize,
    pub objects_received: usize,
    pub tags_received: usize,
}

pub async fn fetch(repo: &Repository, tree: &str, remote: &str) -> Result<FetchReport>
```

Downloads the new snapshots, objects, and tags of **all** remote branches and updates `refs/remotes/<remote>/*`. It never touches local branches or working files.

## Pull

```rust
pub struct PullReport {
    pub fetch: FetchReport,
    pub branch: String,
    pub outcome: MergeOutcome,
}

pub async fn pull(repo: &Repository, tree: &str, remote: &str, branch: Option<&str>) -> Result<PullReport>
```

Fetches, then integrates `<remote>/<branch>` into the local branch (default: the current branch): a fast-forward plus checkout when possible, otherwise `Repository::merge`. `outcome` is the resulting `MergeOutcome`; `MergeOutcome::Conflicts` leaves a conflicted merge to resolve with `continue_merge` or `abort_merge` (see [Merge and diff](/docs/protocol/merge-and-diff#merge-state)).

## Clone

```rust
pub async fn clone(server: &str, tenant: &str, tree_name: &str, dest: &Path) -> Result<Repository>
```

Clones `<tenant>/<tree_name>` from `server` into `dest`, which must not exist or must be empty. It initializes the worktree, sets `[remote.origin]`, sets the tree id and remote name to match the server, fetches, creates a local branch for every remote branch, and checks out the default branch.

## Staged snapshots

```rust
pub struct StagedInfo {
    pub snapshot_id: String,
    pub author: String,
    pub branch: String,
    pub files_changed: Vec<String>,
    pub files_added: u32,
    pub files_modified: u32,
    pub files_deleted: u32,
    pub message: Option<String>,
    pub staged_at: chrono::DateTime<chrono::Utc>,
}

pub async fn stage(repo: &Repository, tree: &str, remote: &str) -> Result<StagedInfo>
pub async fn list_staged(repo: &Repository, tree: &str, remote: &str, branch: Option<&str>) -> Result<Vec<StagedInfo>>
```

| Function | Behavior |
|---|---|
| `stage` | Uploads the working state as a staged snapshot: builds a manifest from the working directory, uploads missing objects, and sends `Stage` with the change summary against head. Returns what was staged. The server keeps one staged snapshot per (tree, account, branch); a newer stage replaces it and a push clears it. |
| `list_staged` | Team-wide staged snapshots for `tree`, optionally limited to one branch. Used by `wt status --team`. |

## Example

```rust
use std::path::Path;

use worktree_sdk::{remote, MergeOutcome, Repository, Result};

#[tokio::main]
async fn main() -> Result<()> {
    let server = "http://localhost:7420";
    let password = std::env::var("WT_PASSWORD").unwrap_or_default();
    let me = remote::login(server, "ada", &password).await?;
    println!("logged in as {} (tenant {})", me.username, me.tenant);

    let repo = remote::clone(server, "ada", "my-project", Path::new("my-project")).await?;
    let tree = repo.root_tree()?.name;

    // ... edit files, then share work in progress
    let staged = remote::stage(&repo, &tree, "origin").await?;
    println!("staged {} changed files", staged.files_changed.len());

    for s in remote::list_staged(&repo, &tree, "origin", None).await? {
        println!("{} on {}: {:?}", s.author, s.branch, s.message);
    }

    let pulled = remote::pull(&repo, &tree, "origin", None).await?;
    if let MergeOutcome::Conflicts { conflicts } = pulled.outcome {
        eprintln!("{} conflicts to resolve", conflicts.len());
    }
    Ok(())
}
```
