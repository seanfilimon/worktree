`worktree-sdk` (`crates/worktree-sdk`) is the local W0rkTree engine. Everything that touches a `.wt/` directory lives in this crate; the CLI (`wt`), the background daemon (`worktree-bg`), and the Git bridge (`worktree-git`) are thin layers over it. Anything `wt` can do, an embedding program can do too: editor integrations, CI helpers, migration scripts, or custom clients.

<Callout type="warn" title="Pre-1.0 API">
  The SDK is not published to crates.io and its API may change before 1.0. Only the Rust crate exists; there is no Node.js SDK yet (see the [roadmap](/roadmap)).
</Callout>

## Module map

| Module | Purpose |
|---|---|
| `lib` | Crate root. Re-exports `Repository`, `ObjectHash`, `ObjectStore`, `Result`, `SdkError`, and every type in `model`. |
| `model` | Data types shared by all consumers: `Snapshot` (with `dependencies`, `reverts`, `signature`), `Dependency`, `SnapshotSignature`, `Manifest`, `ManifestEntry`, `TreeInfo`, `BranchInfo`, `TagInfo`, `StatusReport`, `FileChange`, `ChangeKind`, option structs (`InitOptions`, `SnapshotOptions`, `SwitchOptions`, `MergeOptions`, `RevertOptions`, `DiffOptions`), `MergeStrategy`, `MergeOutcome`, `MergeState`, `MergeStatus`, `ConflictInfo`, `ConflictHunk`, `ConflictKind`, `ConflictResolution`, `FileDiff`, `ReflogEntry`, `ReflogExpireReport`. |
| `store` | `ObjectStore`: the content-addressed store under `.wt/objects/` (BLAKE3, raw bytes, atomic writes), FastCDC chunking for files over 8 MiB (`CHUNK_THRESHOLD`, `ChunkList`, `read_entry`). `hash_bytes(data)`. |
| `config` | `WorktreeConfig` (`.wt/config.toml`) with dotted-key `get` / `set` / `entries`, the user and tree configuration layers, `wt_home()` for `$WT_HOME`, and `parse_size`. |
| `repo` | `Repository`: lifecycle, trees, status, snapshots, revisions, branches, merge and resolution, revert, restore, diff, tags, reflog and expiry, ignores, shallow and restricted paths, and low-level ref operations. See [Repository](/docs/sdk/repository). |
| `diff` | Pure text diffing: `diff_lines`, `unified_diff`, `word_diff`, `diff_stat`, `similarity`, `is_binary`. See [Merge and diff](/docs/protocol/merge-and-diff#diff). |
| `merge` | Pure merge algorithms: `merge_text` / `merge_text_with` (diff3, strategies), `merge_manifests`, `merge_executable`, `merge_base`. See [Merge and diff](/docs/protocol/merge-and-diff). |
| `scan` | Pure content scanning: `scan_secrets` and the configurable `SecretScanner`, `detect_license` (SPDX), `chunk_boundaries` (FastCDC). |
| `hooks` | Discovery and execution of `pre-snapshot` / `post-snapshot` hooks (`find_hooks`, `Phase`). See [Hooks](/docs/cli/configuration#hooks). |
| `signing` | Ed25519 snapshot signing: local key store under `$WT_HOME/keys/`, `signed_payload`, `sign_snapshot`, `verify_local`, `verify_with_keys`. See [Snapshot signing](/docs/cli/signing). |
| `remote` | Client for the server: credentials, login (with MFA) and registration, ping, push, fetch, pull, clone (with shallow options), stage, unstage, list staged, branch watching, declarative access (`remote::access`), a typed gRPC client (`SyncClient`) and a REST client (`RestClient`). See [Remote](/docs/sdk/remote). |
| `ipc` | CLI ⇄ daemon protocol: request/response types, `bg.json` discovery with the IPC token, `send`. See [Daemon IPC](/docs/sdk/ipc). |
| `error` | `SdkError` and `Result<T>`. |

## Adding the dependency

The crate is consumed as a path (or Git) dependency from a checkout of the repository:

```toml
[dependencies]
worktree-sdk = { path = "../worktree/crates/worktree-sdk" }
# Needed only for the async `remote` and `ipc` functions
tokio = { version = "1", features = ["macros", "rt-multi-thread"] }
```

Local operations (`Repository`, `ObjectStore`, `diff`, `merge`, `scan`, `signing`) are synchronous. The `remote` functions and `ipc::send` are `async` and run on Tokio.

## Errors

Every fallible function returns `worktree_sdk::Result<T>`, an alias for `std::result::Result<T, SdkError>`. `SdkError` is a `thiserror` enum; match on the variants you handle and display the rest.

| Area | Variants |
|---|---|
| Repository | `NotAWorktree`, `AlreadyInitialized`, `InvalidConfig(String)`, `InvalidArgument(String)` |
| Trees | `TreeNotFound(String)`, `TreeExists(String)` |
| Branches and tags | `BranchNotFound(String)`, `BranchExists(String)`, `TagExists(String)`, `TagNotFound(String)` |
| Revisions and objects | `SnapshotNotFound(String)`, `AmbiguousId(String)`, `InvalidRevision(String)`, `ObjectNotFound(String)`, `CorruptObject(String, String)` |
| Snapshots and working tree | `NoChanges`, `DirtyWorkingTree(usize)`, `SecretsDetected(String)` |
| Merge | `MergeConflict(String)`, `MergeInProgress`, `NoMergeInProgress` |
| Server policy | `BranchProtection(String)`, `PermissionDenied(String)`, `PushRejected(String)` |
| Remote | `RemoteNotConfigured(String)`, `NotLoggedIn(String)`, `Remote(String)` |
| Daemon | `DaemonNotRunning` |
| Generic | `Io(std::io::Error)`, `Serialization(String)`, `Other(String)` |

A failing `pre-snapshot` hook surfaces as `Other("pre-snapshot hook failed: ...")`, and a shallow history that is too short for an operation as `InvalidArgument` with a hint to run `wt fetch --deepen N`. `std::io::Error`, `serde_json::Error`, and TOML (de)serialization errors convert into `SdkError` automatically, so `?` works on them.

## Minimal example

Create a worktree, write a file, snapshot it, and print the log:

```rust
use std::path::Path;

use worktree_sdk::{InitOptions, Repository, Result, SnapshotOptions};

fn main() -> Result<()> {
    let repo = Repository::init(Path::new("demo"), InitOptions::default())?;
    let tree = repo.root_tree()?.name;

    std::fs::write(repo.root().join("README.md"), "hello\n")?;

    let snap = repo.snapshot(
        &tree,
        SnapshotOptions { message: "First snapshot".into(), ..Default::default() },
    )?;
    println!("created {}", snap.short_id());

    for s in repo.log(&tree, None, Some(10))? {
        println!("{} {} {}", s.short_id(), s.author, s.message);
    }
    Ok(())
}
```

`Repository::snapshot` runs the same pipeline as `wt snapshot`: hooks (unless `skip_hooks`), the configured secret scan (unless `skip_secret_scan`), signing when `[signing] auto` is set or `sign` is true, and the reflog entry.

Open an existing worktree from any directory inside it with `Repository::open`, and push with the async remote API:

```rust
use std::path::Path;

use worktree_sdk::{remote, Repository, Result};

#[tokio::main]
async fn main() -> Result<()> {
    let repo = Repository::open(Path::new("."))?;
    let tree = repo.tree_for_path(Path::new("."))?.name;

    let report = remote::push(&repo, &tree, "origin", None).await?;
    if report.up_to_date {
        println!("{} is up to date", report.branch);
    } else {
        println!("pushed {} snapshots to {}", report.snapshots_sent, report.branch);
    }
    Ok(())
}
```

<Callout type="info" title="Tests">
  Code that logs in, signs snapshots, reads the user configuration or talks to the daemon reads and writes `$WT_HOME`. Set `WT_HOME` to a temporary directory in tests so they never touch real credentials or keys.
</Callout>
