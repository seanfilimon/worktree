The REST API is served under `/api/v1` on the same port as gRPC (default `http://localhost:7420`). Requests and responses are JSON unless noted, and JSON field names are the `json` tags of the Go types in `services/server-go/internal/domain`. The admin panel and the server-side `wt` commands (`wt mr`, `wt trees`, `wt iam`, `wt admin`, ...) use this API; anything they can do, you can script.

`wt` uses gRPC for push, pull, stage, tags and access-config sync (see [Sync protocol](/docs/protocol/sync-protocol)). This page documents the conventions and the core endpoints in detail; the [catalogue](#endpoint-catalogue) lists every other group with a link to the page that explains it. Every server also serves a machine-readable OpenAPI 3.1 description at `GET /api/v1/openapi.yaml`, and `wt api` makes raw authenticated calls; see [OpenAPI and wt api](/docs/server/openapi).

## Conventions

### Authentication

Send a bearer token in the `Authorization` header:

```text
Authorization: Bearer <token>
```

Tokens come from `POST /api/v1/auth/login` (a session, valid 30 days), `POST /api/v1/auth/register`, `POST /api/v1/auth/tokens` (a personal API token) or service-account keys. The same token works for gRPC, so a token from `wt login` (stored in `$WT_HOME/credentials.toml`) is valid here too. `GET` requests may pass the token as `?access_token=` instead, for clients such as `EventSource` that cannot set headers.

Requests without a token are anonymous; they can reach `/healthz`, `/metrics`, registration, login, invitation previews, the action catalogue and read endpoints of `public` trees. A request with an **invalid** token is rejected with `401` and `WWW-Authenticate: Bearer realm="worktree"`; it is never downgraded to anonymous. Authorization is described in [Access control](/docs/server/access-control); the **Auth** columns below name the check each endpoint performs.

### Errors

Every error uses the same envelope:

```json
{"error":{"code":"not_found","message":"tree acme/payments not found"}}
```

| `code` | HTTP | Typical cause |
|---|---|---|
| `bad_request` | 400 | Malformed JSON, unknown field, missing or invalid value. |
| `unauthenticated` | 401 | Missing, invalid, expired or revoked token; wrong password; disabled account. |
| `forbidden` | 403 | Authenticated but not allowed; registration disabled. |
| `path_denied` | 403 | A policy denies reading that path. |
| `branch_protection`, `license_violation`, `access_denied`, `review_required`, `signature_required`, `ci_checks_failed` | 403 | A protection, license or policy rule refuses the operation. |
| `not_found` | 404 | Unknown resource or API path, or not visible to the caller. |
| `method_not_allowed` | 405 | Wrong method; the `Allow` header lists the right ones. |
| `conflict` | 409 | Name already taken; concurrent update. |
| `quota_exceeded`, `merge_blocked`, `linked_group`, `managed_by_config`, `last_owner` | 409 | Tenant quota reached; merge request not mergeable; member of a linked group; object managed by declarative config; last owner of a tenant. |
| `merge_conflict`, `merge_method_not_allowed`, `gc_running` | 409 | Server-side merge has conflicts (the body lists `conflicts`); merge method refused by protection; a GC run is already in progress. |
| `binary_file` | 422 | Blame of a binary file. |
| `payload_too_large` | 413 | JSON body over 1 MiB (release assets: 64 MiB). |
| `unsupported_media_type` | 415 | Body is not `application/json`. |
| `rate_limited` | 429 | Rate limit reached; see `Retry-After`. |
| `license_restricted` | 451 | A license rule withholds the content from the caller. |
| `internal` | 500 | Unexpected error; logged with the `X-Request-Id`, no details returned. |
| `not_implemented` | 501 | The feature's service is not configured. |

Every response carries `X-Request-Id`. Responses containing secrets send `Cache-Control: no-store`.

### Path parameters

| Parameter | Meaning |
|---|---|
| `{tenant}` | Tenant slug (lowercase `a-z`, `0-9`, `-`). A user's personal tenant slug is their username. |
| `{tree}` | Tree name, unique within the tenant. |
| `{username}` | Account username. |
| `{id}` | Snapshot id (UUID), token id, policy id, ... depending on the endpoint. |
| `{n}` | Merge request or TODO number (per tree, starting at 1). |
| `REV` | Where an endpoint takes a revision: a snapshot id or unique prefix of at least 4 characters, a branch or a tag. |

### Formats

- Timestamps are RFC 3339 strings in UTC, for example `"2026-10-20T14:03:11Z"`.
- Ids of tenants, accounts, trees, snapshots, merge requests and tokens are UUID strings.
- Content hashes (`manifest_hash`, file `hash`) are 64-character lowercase hex BLAKE3-256 digests.
- Bodies are strict: unknown fields are rejected and exactly one JSON value is accepted.
- List endpoints return a JSON array (or an object with a named array where noted); an empty result is `[]`.

### `POST /api/v1/auth/register`

Creates an account and its personal tenant (slug = username, kind `user`) with the new account as `owner`, and returns a session token. Returns `403 forbidden` when the server runs with `--allow-registration=false`, and `409 conflict` if the username is taken.

```json
{"username":"alice","email":"alice@example.com","password":"correct horse battery staple"}
```

Response `201`:

```json
{
  "token": "wt_3q8Zr0...",
  "account": {
    "id": "3f2b9c1e-8a4d-4f6e-9b7a-1c2d3e4f5a6b",
    "username": "alice",
    "email": "alice@example.com",
    "display_name": "",
    "tenant_id": "9d8e7f60-1a2b-4c3d-8e9f-0a1b2c3d4e5f",
    "is_admin": false,
    "disabled": false,
    "created_at": "2026-10-20T14:03:11Z"
  }
}
```

Treat tokens as opaque strings.

### `POST /api/v1/auth/login`

Verifies the password and issues a new session token (valid 30 days).

```bash
curl -s -X POST $WT/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"alice","password":"correct horse battery staple"}'
```

Response `200`: `{"token": "...", "account": {...}}`, the same shape as register. For an account with two-factor authentication, the response is a challenge instead:

```json
{"mfa_required": true, "mfa_token": "wtm_...", "account": {"username": "alice"}}
```

Exchange it within 5 minutes with `POST /api/v1/auth/login/mfa` and `{"mfa_token": "wtm_...", "code": "123456"}` (a TOTP code or a recovery code) for the session. A wrong password or a disabled account returns `401 unauthenticated`; repeated failures lock the (username, client IP) pair for a few minutes.

### `POST /api/v1/auth/logout`

Revokes the token used to make the request. No body. Response `204`.

### `GET /api/v1/auth/me`

Returns the caller's account and tenant memberships.

```json
{
  "account": {
    "id": "3f2b9c1e-8a4d-4f6e-9b7a-1c2d3e4f5a6b",
    "username": "alice",
    "email": "alice@example.com",
    "display_name": "",
    "tenant_id": "9d8e7f60-1a2b-4c3d-8e9f-0a1b2c3d4e5f",
    "is_admin": false,
    "disabled": false,
    "created_at": "2026-10-20T14:03:11Z"
  },
  "memberships": [
    {
      "tenant": {"id": "9d8e7f60-1a2b-4c3d-8e9f-0a1b2c3d4e5f", "slug": "alice", "name": "alice", "kind": "user", "plan": "free", "created_at": "2026-10-20T14:03:11Z"},
      "role": "owner"
    },
    {
      "tenant": {"id": "b1c2d3e4-f5a6-4b7c-8d9e-0f1a2b3c4d5e", "slug": "acme", "name": "Acme Corp", "kind": "org", "plan": "free", "created_at": "2026-10-20T15:00:00Z"},
      "role": "developer"
    }
  ]
}
```

### `GET /api/v1/auth/tokens`

Lists the caller's API tokens. Secrets are never returned.

```json
[
  {
    "id": "c0ffee00-1234-4abc-9def-0123456789ab",
    "account_id": "3f2b9c1e-8a4d-4f6e-9b7a-1c2d3e4f5a6b",
    "name": "ci",
    "created_at": "2026-10-20T16:00:00Z",
    "expires_at": "2026-11-19T16:00:00Z",
    "last_used_at": "2026-10-21T08:12:45Z",
    "kind": "api",
    "scopes": ["tree:read", "ci:report"]
  }
]
```

`expires_at`, `last_used_at` and `scopes` are omitted when not set.

### `POST /api/v1/auth/tokens`

Creates a personal API token. `ttl_hours` is optional (omit it for no expiry); `scopes` optionally restricts the token to action patterns such as `tree:read`, `tree:*` or `ci:report`. A token cannot be scoped to something the caller may not do.

```bash
curl -s -X POST $WT/api/v1/auth/tokens \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"ci","ttl_hours":720,"scopes":["tree:read","ci:report"]}'
```

Response `200`: `{"token": "wt_Xk91...", "api_token": {...}}`. CLI: `wt token create ci --ttl-hours 720 --scope tree:read --scope ci:report`.

<Callout type="warn">
  The raw `token` is returned only once. The server stores only its SHA-256 hash and cannot show it again.
</Callout>

### `DELETE /api/v1/auth/tokens/{id}`

Revokes one of the caller's tokens. Response `204`.

| Method | Path | Auth | Success |
|---|---|---|---|
| `GET` | `/api/v1/tenants` | token | `200` |
| `POST` | `/api/v1/tenants` | token | `201` |
| `GET` | `/api/v1/tenants/{tenant}` | `tenant:read` | `200` |
| `PATCH` | `/api/v1/tenants/{tenant}` | `tenant:admin` (`plan`: server admin) | `200` |
| `GET` | `/api/v1/tenants/{tenant}/members` | `tenant:read` | `200` |
| `PUT` | `/api/v1/tenants/{tenant}/members/{username}` | `tenant:admin` | `200` |

| `GET` | `/api/v1/tenants/{tenant}/usage` | `tenant:read` | `200` |

### `GET /api/v1/tenants`

Returns the tenants visible to the caller.

```json
[
  {"id": "b1c2d3e4-f5a6-4b7c-8d9e-0f1a2b3c4d5e", "slug": "acme", "name": "Acme Corp", "kind": "org", "plan": "free", "created_at": "2026-10-20T15:00:00Z"}
]
```

`kind` is `user` (personal) or `org`. `plan` is a label (`free`, `pro`, `enterprise`). `status`, `status_reason` and `limits` appear when set (see [Operations](/docs/server/operations#tenant-status)).

### `POST /api/v1/tenants`

Creates an organization tenant; the caller becomes its `owner`. `slug` must be lowercase `[a-z0-9-]` and unique (`409 conflict` if taken).

```bash
curl -s -X POST $WT/api/v1/tenants \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"slug":"acme","name":"Acme Corp"}'
```

### `GET /api/v1/tenants/{tenant}/members`

```json
[
  {
    "account": {"id": "3f2b9c1e-8a4d-4f6e-9b7a-1c2d3e4f5a6b", "username": "alice", "email": "alice@example.com", "display_name": "", "tenant_id": "9d8e7f60-1a2b-4c3d-8e9f-0a1b2c3d4e5f", "is_admin": false, "disabled": false, "created_at": "2026-10-20T14:03:11Z"},
    "role": "owner"
  }
]
```

### `PUT /api/v1/tenants/{tenant}/members/{username}`

Adds an existing account to the tenant or changes its role: a built-in role (`owner`, `admin`, `maintainer`, `developer`, `viewer`) or a custom role of the tenant. Only owners can assign `owner`. Fails with `409 quota_exceeded` when the tenant's member limit is reached, and with `409 last_owner` when it would demote the last owner.

```bash
curl -s -X PUT $WT/api/v1/tenants/acme/members/bob \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"role":"developer"}'
```

### `DELETE /api/v1/tenants/{tenant}/members/{username}`

Removes the membership (`409 last_owner` for the last owner). Response `204`.

## Trees

| Method | Path | Auth | Success |
|---|---|---|---|
| `GET` | `/api/v1/tenants/{tenant}/trees` | read (per tree visibility) | `200` |
| `POST` | `/api/v1/tenants/{tenant}/trees` | `tree:create` | `201` |
| `GET` | `/api/v1/trees/{tenant}/{tree}` | `tree:read` | `200` |
| `PATCH` | `/api/v1/trees/{tenant}/{tree}` | `tree:admin` | `200` |

Trees are also created implicitly the first time `wt push` targets a tree that does not exist yet, when the caller has `tree:create`. Such trees are `private` with default branch `main`.

### Tree summary

`GET /api/v1/tenants/{tenant}/trees` returns an array of tree summaries, and `GET /api/v1/trees/{tenant}/{tree}` returns one:

```json
{
  "tree": {
    "id": "e5f6a7b8-c9d0-4e1f-a2b3-c4d5e6f7a8b9",
    "tenant_id": "b1c2d3e4-f5a6-4b7c-8d9e-0f1a2b3c4d5e",
    "name": "payments",
    "description": "Payment service",
    "default_branch": "main",
    "visibility": "private",
    "created_at": "2026-10-20T15:05:00Z",
    "updated_at": "2026-10-21T09:30:00Z"
  },
  "branch_count": 3,
  "snapshot_count": 128,
  "staged_count": 2,
  "open_mr_count": 1
}
```

### `POST /api/v1/tenants/{tenant}/trees`

```bash
curl -s -X POST $WT/api/v1/tenants/acme/trees \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"payments","description":"Payment service","visibility":"private","default_branch":"main"}'
```

`name` is required. `visibility` is `private`, `internal` or `public`. Response `201`: the tree object. Publishes `tree.created` and audits `tree.create`. `409 quota_exceeded` when the tenant's tree limit is reached. CLI: `wt trees create acme/payments --visibility private`.

### `PATCH /api/v1/trees/{tenant}/{tree}`

Updates any subset of `description`, `visibility`, `default_branch`.

```json
{"visibility":"internal"}
```

### `DELETE /api/v1/trees/{tenant}/{tree}`

Deletes the tree and its metadata and publishes `tree.deleted`. Objects that are no longer reachable are removed later by [garbage collection](/docs/server/operations#garbage-collection). Response `204`.

All endpoints in this group require `tree:read`, which anonymous callers have on `public` trees.

| Method | Path | Query | Returns |
|---|---|---|---|
| `GET` | `/api/v1/trees/{tenant}/{tree}/branches` | none | `[branch]` |
| `GET` | `/api/v1/trees/{tenant}/{tree}/snapshots` | `branch`, `limit` (default 50) | `[snapshot]`, newest first |
| `GET` | `/api/v1/trees/{tenant}/{tree}/snapshots/{id}` | none | `{snapshot, files, restricted_count}` |
| `GET` | `/api/v1/trees/{tenant}/{tree}/blob/{snapshot}/{path...}` | none | raw file bytes |

### Branches

```json
[
  {
    "tree_id": "e5f6a7b8-c9d0-4e1f-a2b3-c4d5e6f7a8b9",
    "name": "main",
    "tip": "7a1d5c2e-4b3f-4e6a-9c8d-2f1e0d9c8b7a",
    "protected": true,
    "created_at": "2026-10-20T15:05:00Z",
    "updated_at": "2026-10-21T09:30:00Z"
  }
]
```

`tip` is a snapshot id, or `""` for an empty branch. `protected` is `true` when a [branch protection](/docs/server/branch-protection) rule matches.

```bash
curl -s "$WT/api/v1/trees/acme/payments/snapshots?branch=main&limit=2" \
```

```json
    "manifest_hash": "af1349b9f5f9a1a6a0404dea36dcc9499bcb25c9adc112b7cc9a93cae41f3262",
    "author": "Alice <alice@example.com>",
    "message": "Add refund endpoint",
    "created_at": "2026-10-21T09:28:40Z",
    "auto_generated": false,
    "pushed_by": "3f2b9c1e-8a4d-4f6e-9b7a-1c2d3e4f5a6b",
    "pushed_at": "2026-10-21T09:30:00Z",

    "signature": "aW7c...",

```

`pushed_by` is an account id. `auto_generated` is `true` for daemon auto-snapshots. The optional fields `dependencies` (see [TODOs](/docs/cli/dependencies#wt-todo)), `reverts` (the snapshot a revert undoes), `signature` (base64), `signing_key_id` and `verified` (the server verified the Ed25519 signature on push; see [signing](/docs/cli/signing)) appear when set.

### Snapshot detail

`GET /api/v1/trees/{tenant}/{tree}/snapshots/{id}` returns the snapshot and the file list of its manifest:

```json
{
  "snapshot": {"id": "7a1d5c2e-4b3f-4e6a-9c8d-2f1e0d9c8b7a", "...": "..."},
  "files": [
    {"path": "README.md", "hash": "4f1a...e09c", "size": 1832, "executable": false},
    {"path": "scripts/deploy.sh", "hash": "9b02...71aa", "size": 410, "executable": true}
  ],
  "restricted_count": 0
}
```

Hashes are shortened here; the API returns the full 64 hex characters. Paths the caller may not read (policy path denies, license rules) are left out of `files` and counted in `restricted_count`.

### Blob

`GET /api/v1/trees/{tenant}/{tree}/blob/{snapshot}/{path...}` returns the raw bytes of one file at a snapshot; chunked large files are reassembled. `{path...}` may contain slashes.

```bash
curl -s "$WT/api/v1/trees/acme/payments/blob/7a1d5c2e-4b3f-4e6a-9c8d-2f1e0d9c8b7a/scripts/deploy.sh" \
  -H "Authorization: Bearer $TOKEN" -o deploy.sh
```

A path denied by a policy answers `403 path_denied`; a path withheld by a [license rule](/docs/server/licensing) answers `451 license_restricted`. Blob responses send `X-Content-Type-Options: nosniff`.

### Tags

```json
[
  {
    "tree_id": "e5f6a7b8-c9d0-4e1f-a2b3-c4d5e6f7a8b9",
    "name": "v1.4.0",
    "target": "7a1d5c2e-4b3f-4e6a-9c8d-2f1e0d9c8b7a",
    "message": "Release 1.4.0",
    "tagger": "alice",
    "created_at": "2026-10-21T10:00:00Z"
  }
]
```

Tags reach the server through `wt push` (gRPC `PushTag`) or `POST {tree}/tags {name, target, message?}` (`tree:write`, `target` is a REV); `DELETE {tree}/tags/{name}` needs `tree:admin`. [Tag protections](/docs/server/branch-protection#tag-protection) apply. See the [tags guide](/guides/tags-and-releases).

### Staged snapshots

`GET /api/v1/trees/{tenant}/{tree}/staged?branch=main` lists team-visible work in progress, newest first. Omit `branch` for all branches.

```json
[
  {
    "snapshot_id": "5c4b3a29-1807-4f6e-8d5c-4b3a29180716",
    "tree_id": "e5f6a7b8-c9d0-4e1f-a2b3-c4d5e6f7a8b9",
    "tenant_id": "b1c2d3e4-f5a6-4b7c-8d9e-0f1a2b3c4d5e",
    "account_id": "7e6d5c4b-3a29-4180-9f6e-5d4c3b2a1908",
    "author": "bob",
    "branch_name": "main",
    "files_changed": ["src/refund.rs", "src/lib.rs"],
    "files_added": 1,
    "files_modified": 1,
    "files_deleted": 0,
    "message": "auto: 2 files changed",
    "staged_at": "2026-10-21T11:42:07Z"
  }
]
```

There is at most one staged snapshot per tree, account and branch. `GET {tree}/staged/summary` aggregates them per branch and reports **overlaps** (files staged by two or more accounts). `DELETE {tree}/staged?branch=` removes your own entry (`tree:admin` may add `account=`). See the [staged visibility guide](/guides/staged-visibility).

## Protections

| Method | Path | Auth | Success |
|---|---|---|---|
| `GET` | `/api/v1/trees/{tenant}/{tree}/protections` | `tree:read` | `200` |
| `PUT` | `/api/v1/trees/{tenant}/{tree}/protections` | `tree:admin` | `200` |
| `DELETE` | `/api/v1/trees/{tenant}/{tree}/protections?pattern=` | `tree:admin` | `204` |
| `GET`, `PUT`, `DELETE` | `/api/v1/trees/{tenant}/{tree}/tag-protections` (`DELETE ?pattern=`) | `tree:read` / `tree:admin` | `200` / `204` |

The body of `PUT` is a branch protection, keyed by `pattern`: putting an existing pattern replaces it. `tree_id` is filled in by the server.

```bash
curl -s -X PUT $WT/api/v1/trees/acme/payments/protections \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"pattern":"main","no_direct_push":true,"required_approvals":1,"allowed_pushers":[],"no_delete":true,"require_ci_pass":true,"required_checks":["ci/build"],"require_signed":false,"require_linear":true,"block_on_todos":false}'
```

Response (also the element type of `GET`):

```json
{
  "tree_id": "e5f6a7b8-c9d0-4e1f-a2b3-c4d5e6f7a8b9",
  "pattern": "main",
  "no_direct_push": true,
  "required_approvals": 1,
  "allowed_pushers": [],
  "no_delete": true,
  "require_ci_pass": true,
  "required_checks": ["ci/build"],
  "require_linear": true
}
```

`require_ci_pass`, `required_checks`, `require_signed`, `require_linear` and `block_on_todos` are omitted when false or empty. Delete a rule by pattern (URL-encode it, for example `release%2F*`):

```bash
curl -s -X DELETE "$WT/api/v1/trees/acme/payments/protections?pattern=release%2F*" \
  -H "Authorization: Bearer $TOKEN"
```

Tag protections have `pattern`, `no_delete`, `no_move` and `allowed_taggers`. Semantics are described in [Branch protection](/docs/server/branch-protection).

## Merge requests

| Method | Path | Auth | Success |
|---|---|---|---|
| `GET` | `/api/v1/trees/{tenant}/{tree}/merge-requests?state=` | `tree:read` | `200` |
| `POST` | `/api/v1/trees/{tenant}/{tree}/merge-requests` | `mr:create` | `201` |
| `GET` | `/api/v1/trees/{tenant}/{tree}/merge-requests/{n}` | `tree:read` | `200` |
| `POST` | `.../merge-requests/{n}/approve` | `mr:approve` | `200` |
| `POST` | `.../merge-requests/{n}/review` | `mr:approve` (`commented`: `tree:read`) | `200` |
| `GET` | `.../merge-requests/{n}/checks` | `tree:read` | `200` |
| `GET` | `.../merge-requests/{n}/mergeability` | `tree:read` | `200` |
| `POST` | `.../merge-requests/{n}/merge` | `mr:merge` | `200` |
| `POST` | `.../merge-requests/{n}/close` | author or `mr:merge` | `200` |
| `GET`, `POST` | `.../merge-requests/{n}/comments` | `tree:read` | `200` / `201` |
| `PATCH`, `DELETE` | `.../merge-requests/{n}/comments/{id}` | comment author or `tree:admin` | `200` / `204` |

`state` filters the list: `open`, `merged` or `closed`; omit it for all.

### `POST .../merge-requests`

```bash
curl -s -X POST $WT/api/v1/trees/acme/payments/merge-requests \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"title":"Add refund endpoint","description":"Implements POST /refunds","source_branch":"feature/refunds","target_branch":"main"}'
```

Response `201`, the shape returned by every merge request endpoint:

```json
{
  "id": "a9b8c7d6-e5f4-4a3b-9c2d-1e0f9a8b7c6d",
  "tree_id": "e5f6a7b8-c9d0-4e1f-a2b3-c4d5e6f7a8b9",
  "number": 4,
  "title": "Add refund endpoint",
  "description": "Implements POST /refunds",
  "source_branch": "feature/refunds",
  "target_branch": "main",
  "author_id": "7e6d5c4b-3a29-4180-9f6e-5d4c3b2a1908",
  "author": "bob",
  "state": "open",
  "approvals": [],
  "created_at": "2026-10-21T12:00:00Z",
  "updated_at": "2026-10-21T12:00:00Z"
}
```

After a merge, `state` is `merged` and `merged_at`, `merged_snapshot` (the new target tip) and `merge_method` are present; `linked_group` appears for members of a linked group. Each review entry in `approvals` looks like `{"account_id": "...", "username": "alice", "at": "...", "snapshot_id": "...", "decision": "approved", "body": "..."}`.

### `POST .../merge-requests/{n}/review`

```json
{"decision": "changes_requested", "body": "Needs a test"}
```

`decision` is `approved`, `changes_requested` or `commented`. `/approve` (no body) is shorthand for `approved`; authors cannot approve their own merge request. An approval records the source tip and goes stale when the source moves.

### `GET .../merge-requests/{n}/checks`

Merge readiness: `{"mergeable", "blockers": [{"kind", "message"}], "approvals": {"required", "current", "stale"}, "ci": {"state", "required", "missing"}, "todos": {"blocking_open"}, "methods", "conflicts"}`. See [Branch protection](/docs/server/branch-protection#merge-requests). `GET .../mergeability` reports only the method side (possible methods, default, merge base, conflicts); see [Server-side merges](/docs/server/merging#mergeability).

### `POST .../merge-requests/{n}/merge`

Merges the source into the target and returns the merged merge request. The body is optional: `{"method"?: "fast-forward"|"merge"|"squash", "message"?}`. Without a method the server fast-forwards when it can and otherwise writes a merge snapshot, whichever branch protection allows first.

```bash
curl -s -X POST $WT/api/v1/trees/acme/payments/merge-requests/4/merge \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"method":"squash"}'
```

Refusals, in order of precedence: `409 linked_group` for a member of a linked group, `403 review_required` for missing approvals, `409 merge_blocked` naming the blockers (change requests, CI, TODOs, linearity), `409 merge_method_not_allowed`, `409 merge_conflict` with a `conflicts` list, and `409 conflict` for a fast-forward on diverged branches or a target that moved during the merge. Details: [Server-side merges](/docs/server/merging#rest).

### `POST .../merge-requests/{n}/close`

Closes an open merge request without merging. No body.

## Rate limits

Requests are limited per principal (or per IP for anonymous callers), 1,200 per minute by default. Over the limit the server answers `429 rate_limited` with `Retry-After`, `X-RateLimit-Limit` and `X-RateLimit-Remaining`. See [Rate limiting](/docs/server/operations#rate-limiting).

## CORS

Browser requests are allowed from `http://localhost:5173` (the admin panel's Vite dev server) and from the origins in `--cors-origins` / `WT_CORS_ORIGINS` (`*` allows any). The admin panel served at `/admin/` is same-origin and needs no CORS configuration.
