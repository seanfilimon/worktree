The server is configured with command-line flags and `WT_*` environment variables only. There is no configuration file. Run `worktree-server --help` for the list below, and `worktree-server --version` to print the version. `worktree-server restore` is the only subcommand (offline restore of a backup, see [S3 storage and backups](/docs/server/storage-backends#restore)).

## Flags and environment variables

### Core

| Flag | Environment variable | Default | Description |
|---|---|---|---|
| `--addr` | `WT_ADDR` | `:7420` | Listen address. One port serves gRPC, REST, SSE, `/healthz`, `/metrics` and `/admin/`. Use `127.0.0.1:7420` to listen on loopback only (recommended behind a reverse proxy). |
| `--data` | `WT_DATA` | `./wt-data` | Data directory holding `meta.db` (bbolt metadata), `objects/` (with the disk object store), `backups/`, `codeindex/` and `mirrors/`. Created if missing. See [Storage](/docs/server/storage). |
| `--admin-user` | `WT_ADMIN_USER` | `admin` | Username of the server admin account managed at startup. |
| `--admin-password` | `WT_ADMIN_PASSWORD` | unset | When set, the server ensures the admin account exists at startup: it is created if missing; an existing account is made server admin and its password is reset to this value when it differs (existing tokens stay valid). |
| `--admin-dir` | `WT_ADMIN_DIR` | unset | Static admin panel build (normally `apps/admin/dist`) served at `/admin/` with `index.html` fallback. When unset, the panel is not served. |
| `--allow-registration` | `WT_ALLOW_REGISTRATION` | `true` | Allow self-service registration (`POST /api/v1/auth/register`, `wt register`). Server admins can always create accounts with `wt admin account-create`. |
| `--public-url` | `WT_PUBLIC_URL` | unset | External base URL of the server; the default SSO redirect URL is `<public-url>/api/v1/auth/sso/callback`. |
| `--shutdown-timeout` | `WT_SHUTDOWN_TIMEOUT` | `15s` | Bound on graceful shutdown. |

### Logging and HTTP

| Flag | Environment variable | Default | Description |
|---|---|---|---|
| `--log-level` | `WT_LOG_LEVEL` | `info` | `debug`, `info`, `warn` or `error`. |
| `--log-format` | `WT_LOG_FORMAT` | `text` | `text` or `json` (Go `log/slog` to stderr). |
| `--cors-origins` | `WT_CORS_ORIGINS` | unset | Comma-separated extra browser origins; `*` allows any origin. `http://localhost:5173` (the admin panel's Vite dev server) is always allowed. |
| `--trusted-proxies` | `WT_TRUSTED_PROXIES` | unset | Comma-separated reverse-proxy IPs or CIDRs whose `X-Forwarded-For` names the client. The client IP feeds policy IP conditions, rate limits and audit records. See [Trusted proxies](/docs/server/operations#trusted-proxies). |

### TLS

| Flag | Environment variable | Default | Description |
|---|---|---|---|
| `--tls-cert` | `WT_TLS_CERT` | unset | PEM certificate file. With `--tls-key`, the port serves HTTPS and gRPC over TLS (ALPN `h2`). |
| `--tls-key` | `WT_TLS_KEY` | unset | PEM private key for `--tls-cert`. |
| `--tls-client-ca` | `WT_TLS_CLIENT_CA` | unset | PEM CA bundle; client certificates signed by it are required (mTLS). |

See [TLS](/docs/server/operations#tls).

### Garbage collection and retention

| Flag | Environment variable | Default | Description |
|---|---|---|---|
| `--gc-interval` | `WT_GC_INTERVAL` | `24h` | Period of automatic garbage collection; `0` disables the ticker (GC can still run on demand). |
| `--gc-grace` | `WT_GC_GRACE` | `720h` | How long an unreachable object stays marked before it is deleted. |
| `--staged-retention` | `WT_STAGED_RETENTION` | `168h` | Staged snapshots older than this expire; `0` keeps them. |
| `--audit-retention` | `WT_AUDIT_RETENTION` | `0` | Audit events older than this are deleted by GC; `0` keeps them forever. |

See [Garbage collection](/docs/server/operations#garbage-collection).

### Limits

| Flag | Environment variable | Default | Description |
|---|---|---|---|
| `--rate-limit` | `WT_RATE_LIMIT` | `1200` | Requests per minute per principal (or per IP for anonymous callers); `0` disables rate limiting. |
| `--default-max-trees` | `WT_DEFAULT_MAX_TREES` | `0` | Default maximum trees per tenant; `0` is unlimited. |
| `--default-max-storage` | `WT_DEFAULT_MAX_STORAGE` | `0` | Default maximum stored bytes per tenant; `0` is unlimited. |

Per-tenant overrides are set with `wt admin limits`. See [Quotas](/docs/server/operations#quotas) and [Rate limiting](/docs/server/operations#rate-limiting).

### Webhooks and storage

| Flag | Environment variable | Default | Description |
|---|---|---|---|
| `--compress-objects` | `WT_COMPRESS_OBJECTS` | `true` | Store new objects zstd-compressed when that saves at least 10 %. With `false`, new objects are written raw; compressed objects are still read. See [Object compression](/docs/server/operations#object-compression). |
| `--webhook-allow-private` | `WT_WEBHOOK_ALLOW_PRIVATE` | `false` | Allow webhook targets on loopback, link-local and private addresses (disables the SSRF guard for every tenant). See [Webhook targets](/docs/server/operations#webhook-targets). |

### Object storage and backups

| Flag | Environment variable | Default | Description |
|---|---|---|---|
| `--object-store` | `WT_OBJECT_STORE` | `disk` | `disk` (objects in `<data>/objects/`) or `s3`. `meta.db` always stays in the data directory. |
| `--s3-endpoint` | `WT_S3_ENDPOINT` | unset | S3 API `host:port` or `http(s)://host:port`, for example `s3.amazonaws.com` or `minio:9000`; `http://` implies `--s3-insecure`. Required for `s3`. |
| `--s3-bucket` | `WT_S3_BUCKET` | unset | Bucket holding the objects; created when missing. Required for `s3`. |
| `--s3-prefix` | `WT_S3_PREFIX` | unset | Key prefix inside the bucket, for example `wt/`. |
| `--s3-region` | `WT_S3_REGION` | discovered | Bucket region. |
| `--s3-access-key`, `--s3-secret-key` | `WT_S3_ACCESS_KEY`, `WT_S3_SECRET_KEY` | unset | Static credentials, given together; prefer the environment variables. When empty, the `AWS_*` / `MINIO_*` environment and then the instance role are used. |
| `--s3-insecure` | `WT_S3_INSECURE` | `false` | Plain HTTP to the S3 endpoint. |
| `--backup-interval` | `WT_BACKUP_INTERVAL` | `0` | Period of scheduled backups into `<data>/backups` (at least `1m`); `0` disables them. |
| `--backup-keep` | `WT_BACKUP_KEEP` | `7` | Scheduled backups to keep; `0` keeps all. Backups made by people are never pruned. |

See [S3 storage and backups](/docs/server/storage-backends). Restoring is a separate subcommand, `worktree-server restore`, described [there](/docs/server/storage-backends#restore).

### Notifications (SMTP)

| Flag | Environment variable | Default | Description |
|---|---|---|---|
| `--smtp-url` | `WT_SMTP_URL` | unset | Send notification email through `smtp://user:pass@host:587` (STARTTLS when offered) or `smtps://user:pass@host:465` (implicit TLS). Without it no email is sent. Prefer the environment variable; the URL is never logged. |
| `--smtp-from` | `WT_SMTP_FROM` | `"W0rkTree" <noreply@HOST>` | From address; `HOST` is the host of `--public-url`, else `localhost`. |

See [Notifications](/docs/server/notifications#email).

### Code search index

| Flag | Environment variable | Default | Description |
|---|---|---|---|
| `--code-index-memory` | `WT_CODE_INDEX_MEMORY` | `256MiB` | Memory cap of loaded index segments (`256MiB`, `1G`, `512MB` or bytes; `0` = unlimited). Evicted segments stay on disk in `<data>/codeindex/`. |
| `--code-index-branches` | `WT_CODE_INDEX_BRANCHES` | `10` | Most branches indexed per tree (1-1000), used by `branches=all` searches. |

See [Code search](/docs/server/code-search#the-persistent-index).

### Git mirrors

| Flag | Environment variable | Default | Description |
|---|---|---|---|
| `--git-binary` | `WT_GIT_BINARY` | `git` | git executable (2.31 or newer) used by Git mirrors. When it is missing, mirrors stay configurable but are disabled. |
| `--mirror-allow-local` | `WT_MIRROR_ALLOW_LOCAL` | `false` | Allow `file://` mirror remotes and mirror hosts on loopback, link-local and private addresses. |

See [Git mirrors](/docs/server/mirrors).

### Profiling

| Flag | Environment variable | Default | Description |
|---|---|---|---|
| `--pprof` | `WT_PPROF` | `false` | Serve Go runtime profiles at `/debug/pprof` to server admins (`404` without the flag). |

See [Performance](/docs/server/performance#profiling-a-running-server). A hidden `--webhook-retry-schedule` flag replaces the webhook retry delays and exists for tests only.

### Precedence and syntax

- A flag on the command line overrides the matching environment variable, which overrides the default.
- Durations use Go syntax: `90s`, `15m`, `24h`, `720h`.
- `--allow-registration`, `--compress-objects`, `--s3-insecure`, `--mirror-allow-local`, `--webhook-allow-private` and `--pprof` are boolean flags; turn them off with an explicit value, `--allow-registration=false`. The environment variables accept `true` or `false`.
- Invalid values make the server exit with code `2`; a runtime error exits with `1`.

### Fixed settings

| Setting | Value |
|---|---|
| Session token lifetime (password, MFA or SSO login) | 30 days |
| gRPC maximum message size | 64 MiB, both directions |
| REST JSON request body | 1 MiB (`413 payload_too_large`) |
| Release asset upload | 64 MiB |
| SSE heartbeat interval | 15 seconds |
| Audit query page | 100 events by default, at most 1000 (`format=ndjson` has no limit) |
| Webhook delivery timeout and retries | 10 seconds; retries after 1 m, 5 m, 30 m, 2 h; deactivated after 20 consecutive failures |
| Webhook delivery log | 200 newest deliveries per hook, at most 30 days |
| Code search | Text files up to 1 MiB, at most 1000 hits and 5 seconds per query |
| Notification retention | 1000 per account, 90 days; email retries after 30 s, 2 m, 10 m, 30 m |
| Git mirrors | 10 per tree; automatic syncs 5 seconds after a push, retried after 1 m, 5 m, 30 m, 2 h; 10 minute push timeout |

Single sign-on is not a flag: a server admin configures it at runtime with [`wt sso set`](/docs/cli/iam#wt-sso) or `PUT /api/v1/admin/sso`. Encryption at rest is not built yet (see the [roadmap](/roadmap)); use volume encryption or your object store's server-side encryption.


</Tab>

</Tab>

### Production-style, configured through the environment

<Tabs items={['bash', 'PowerShell']}>
<Tab value="bash">

```bash
export WT_ADDR=:7420
export WT_DATA=/var/lib/worktree/data
export WT_ADMIN_USER=root
export WT_ADMIN_PASSWORD='use-a-long-random-secret'
export WT_ADMIN_DIR=/opt/worktree/admin
export WT_ALLOW_REGISTRATION=false
export WT_TLS_CERT=/etc/worktree/tls/fullchain.pem
export WT_TLS_KEY=/etc/worktree/tls/privkey.pem
export WT_PUBLIC_URL=https://wt.example.com
export WT_LOG_FORMAT=json
export WT_AUDIT_RETENTION=8760h
export WT_DEFAULT_MAX_STORAGE=10737418240
export WT_BACKUP_INTERVAL=24h
export WT_SMTP_URL='smtp://wt-mailer:secret@smtp.example.com:587'
export WT_SMTP_FROM='W0rkTree <worktree@example.com>'
./worktree-server
```

</Tab>
<Tab value="PowerShell">

```powershell
$env:WT_ADDR = ':7420'
$env:WT_DATA = 'D:\worktree\data'
$env:WT_ADMIN_USER = 'root'
$env:WT_ADMIN_PASSWORD = 'use-a-long-random-secret'
$env:WT_ADMIN_DIR = 'D:\worktree\admin'
$env:WT_ALLOW_REGISTRATION = 'false'

```

</Tab>
</Tabs>

### Overriding one value with a flag

```bash
WT_ADDR=:7420 ./worktree-server --addr 127.0.0.1:9000
```

The server listens on `127.0.0.1:9000` because the flag wins over `WT_ADDR`.

<Callout type="warn" title="Secrets">
  Prefer `WT_ADMIN_PASSWORD` over `--admin-password` outside local testing; command-line arguments are visible to other users in process listings. With systemd, load it from an `EnvironmentFile` readable only by the service user. See [Deployment](/docs/server/deployment).
</Callout>
