title: Code Search
description: Search file contents and symbol definitions across every tree you can read with wt search code or the REST API - literal, RE2 and symbol queries, any branch or all branches, a persistent on-disk index, and access rules.
---


Code search answers "which lines of which files contain X" and "where is the function, type or constant X defined" across the trees you may read. By default it searches the **tip of each tree's default branch**; a query may name another branch or ask for all branch tips. Code matching is line based, like `grep`. Since v0.7 the index is **persistent** (it survives restarts) and also holds **symbols**. The [Code search specification](https://github.com/seanfilimon/worktree/blob/main/crates/worktree-protocol/specs/server/CodeSearch.md) is normative.

## Search from the CLI

```text
wt search code QUERY [--tree TENANT/TREE] [--tenant T] [--path GLOB]
                     [-E|--regex] [-i|--ignore-case] [--context N] [-n|--limit N]
                     [--symbol [--kind KIND[,KIND...]]...]
                     [--branch B | --all-branches]
```

```bash
wt search code 'fn main' --path '*.rs'
wt search code -E -i 'todo|fixme' --tree acme/web --context 1
wt search code 'STRIPE_API' --tenant acme --limit 200
wt search code --symbol parse --kind function,method
wt search code needle --all-branches
wt search code 'retry_after' --json | jq -r '.hits[] | "\(.tree):\(.path):\(.line)"'
```

| Flag | Meaning |
|---|---|
| `QUERY` | Literal text (at least 3 characters), with `--regex` an RE2 expression, or with `--symbol` a name or part of one (1 character is enough) |
| `--tree TENANT/TREE` | Search one tree (the global `--tree` flag, written `TENANT/TREE` here) |
| `--tenant T` | Search the trees of one tenant. Without `--tree` and `--tenant`: every tree you may read |
| `--path GLOB` | Only files matching the glob. `*.go` matches at any depth, `src/**/*.rs` is anchored at the tree root, a directory covers its files |
| `-E`, `--regex` | Treat `QUERY` as an RE2 expression, matched per line (`^` and `$` anchor at line boundaries) |
| `-i`, `--ignore-case` | Ignore case (Unicode case folding). The CLI is case-sensitive otherwise |
| `--context N` | Lines of context before and after each hit, 0-10 (default 0). `-C` stays the global "run in directory" flag |
| `-n`, `--limit N` | Maximum matching lines or symbols, 1-1000 (server default 50) |
| `--symbol` | Search symbol definitions instead of lines (see [Symbols](#symbols)); conflicts with `--regex` and `--context` |
| `--kind KIND` | With `--symbol`: only these kinds, comma-separated or repeated |
| `--branch B` | Search branch `B` instead of each tree's default branch |
| `--all-branches` | Search every indexed branch tip (see [Branches](#branches)) |

Output is `TENANT/TREE:PATH:LINE:TEXT` per hit (`TENANT/TREE@BRANCH:...` with `--branch` or `--all-branches`). Context lines use `-` instead of `:`, groups are separated by `--`, and literal matches are highlighted when colors are on. A truncated result ends with a note.

```text
acme/web:src/main.rs-11-// entry point
acme/web:src/main.rs:12:fn main() {
acme/web:src/main.rs-13-    run();
--
acme/web:tools/gen/main.rs:3:fn main() -> anyhow::Result<()> {
```

`wt search QUERY` (without `code`) still searches tenant, tree, branch and account names; see [`wt search`](/docs/cli/administration#wt-search). The admin panel has the same search at `/admin/search/code` (with a **Code / Symbols** toggle, a kind filter and a branch selector) and in its command palette.

## What is searched

- The **default branch tip** of each tree unless the query names a branch or all branches. Tags, staged snapshots and history are not searched.
- Text files up to **1 MiB**. Binary files (a NUL byte in the first 8000 bytes), larger files and chunked files are skipped.
- The index is built lazily: a branch is indexed by the first search that covers it, and rebuilt when its tip moves (on `branch.pushed`, including server-side merges, and whenever a search sees a newer tip). Rebuilds reuse the content of unchanged files, so only new or changed blobs are read. Deleting a branch or tree drops its index.
- A first search of a large tree can take longer: a search returns what it found within its time budget, and the build finishes in the background for later searches.

## Symbols

`--symbol` (REST: `GET /api/v1/search/symbols`) finds **definitions** whose names contain the query, case-insensitively, ranked **exact > prefix > substring** (exact matches in the query's case first, then shorter names).

```bash
wt search code --symbol parse_config
wt search code --symbol Handler --kind struct,interface --tree acme/api
```

```text
acme/web:src/config.rs:5: function parse_config pub fn parse_config(s: &str) -> Config
acme/web:src/config.rs:10: method Config.parse_strict pub fn parse_strict(&self) -> bool
```

A regex-based extractor recognises definitions by file extension:

| Language | Extensions | Kinds |
|---|---|---|
| Go | `.go` | `function`, `method` (container = receiver type), `struct`, `interface`, `type`, `const` |
| Rust | `.rs` | `function`, `method` (in `impl` and `trait` blocks), `struct`, `enum`, `trait`, `type`, `const` (`const` and `static`) |
| TypeScript, JavaScript | `.ts .tsx .mts .cts .js .jsx .mjs .cjs` | `function` (declarations and `const f = (...) =>`), `class`, `method`, `interface`, `type`, `enum`, `const` (top level) |
| Python | `.py .pyi` | `function`, `class`, `method`, `const` (top-level `UPPER_CASE = ...`) |
| Java | `.java` | `class` (and `record`), `interface`, `enum`, `method` (including constructors), `const` (`static final`) |
| C, C++ | `.c .h .cc .cpp .cxx .c++ .hpp .hh .hxx .h++ .ipp` | `function` (definitions, function-like macros), `method`, `struct`, `class`, `enum`, `type` (`typedef`, `using`), `const` (`#define`, `const`, `constexpr`) |

Only top-level declarations, members of type bodies and declarations inside namespaces or modules are reported, never local definitions inside function bodies; comments and string literals are skipped. Each symbol has a name, kind, line, container (the enclosing type of a method), the defining line as signature (at most 200 bytes) and the language. The extractor is heuristic: unusual formatting can hide or invent a symbol.

## Branches

| Query | Branch tips searched per tree |
|---|---|
| (default) | The default branch |
| `--branch B` (`branch=B`) | Branch `B`; trees without it contribute nothing |
| `--all-branches` (`branches=all`) | The default branch and the most recently updated other branches, up to `--code-index-branches` (default 10) per tree |

Hits are ordered by tenant, tree, branch (default branch first, then by name), path and line. A file version already searched on an earlier branch is skipped, so a file unchanged on a feature branch is reported once, on the default branch. Branches with identical tips share one index segment.

## The persistent index

The index of every searched tree lives under `<data>/codeindex/`: one immutable, checksummed **segment** per indexed manifest (shared by branches with the same tip) plus a `state.json` per tree. New segments are written to a temporary file and renamed into place, so a crash always leaves a consistent index; a segment with another format version, a failing checksum or a structural error is discarded and rebuilt from the object store.

- **After a restart** nothing is rebuilt unless a branch tip changed: segments are loaded from disk on first use (a 3,000-file tree loads in about 10 ms).
- **Memory** is capped by an LRU of loaded segments, `--code-index-memory` (default `256MiB`, `0` = unlimited); evicted segments stay on disk and are loaded again when needed. Plan for about 3.5 times the indexed source size per loaded tree.
- **Branches per tree** are capped by `--code-index-branches` (default 10, 1-1000); indexing one more drops the least recently searched non-default branch.

```bash
wt admin code-index                     # memory against the cap, disk use, builds, per-tree status
wt admin code-index rebuild acme/web    # discard and rebuild one tree's index
wt admin code-index rebuild             # every indexed tree
```

Both need server administrator rights. The admin panel's code search page has an **Index status** panel for server admins with per-tree **Rebuild** buttons. If `<data>/codeindex` cannot be created, the index runs in memory only (logged).

| Operation (3,000 files, 4.7 MB, 39,750 symbols) | Time |
|---|---|
| Cold build | 1.66 s |
| Rebuild with every blob reused | 153 ms |
| Load from disk after a restart | 10.5 ms |
| Literal search, rare string | 20 µs |
| Literal search, common word (limit 50) | 0.36 ms |
| Regex with 874 hits | 4.4 ms |
| Symbol search `parse` (limit 50) | 1.9 ms |

Measured with the Go benchmarks on the reference host of [Performance](/docs/server/performance).

## Access rules

Results never show more than the blob endpoint would:

- Only trees where you hold `tree:read` are searched. Anonymous callers search **public** trees only.
- Paths denied to you by a `tree:read` path policy, and paths the tree's [license rules](/docs/server/licensing) withhold, are dropped silently (for code hits and symbols) and do not count towards the limit.
- An explicit `--tree` you may not read answers `401`/`403` like other tree endpoints; in tenant-wide or server-wide searches such trees are skipped.
- The index status and rebuild endpoints require `server:admin`.

## REST

```text
GET  /api/v1/search/code?q=&tenant=&tree=&path=&regex=false&case=false&context=2&limit=50&branch=|branches=all
GET  /api/v1/search/symbols?q=&kind=&tenant=&tree=&path=&limit=50&branch=|branches=all
GET  /api/v1/admin/code-index
POST /api/v1/admin/code-index/rebuild?tree=TENANT/TREE
```

| Parameter | Default | Meaning |
|---|---|---|
| `q` | required | Code: literal text (at least 3 characters, no line breaks) or, with `regex=true`, an RE2 expression; at most 1000 bytes. Symbols: 1-200 bytes |
| `tree` | | `TENANT/TREE`, or `tree=TREE` together with `tenant=T` |
| `tenant` | | Limit to one tenant's trees |
| `path` | | Path glob |
| `regex` | `false` | Code only: treat `q` as a regular expression |
| `case` | `false` | Code only: `true` = case-sensitive. The API default is case-**insensitive**; the CLI sends `case=true` unless `-i` |
| `context` | `2` | Code only: context lines, 0-10 |
| `kind` | all | Symbols only: comma-separated kinds |
| `limit` | `50` | Maximum hits or symbols, 1-1000 (larger values are clamped) |
| `branch`, `branches=all` | default branch | Mutually exclusive |

```bash
curl -s "$WT/api/v1/search/code?q=fn%20main&tree=acme/web&path=*.rs&context=1" \
  -H "Authorization: Bearer $TOKEN"
```

```json
{
  "hits": [
    {"tenant": "acme", "tree": "web", "branch": "main", "snapshot_id": "7a1d5c2e-...",
     "path": "src/main.rs", "line": 12, "text": "fn main() {",
     "before": ["// entry point"], "after": ["    run();"]}
  ],
  "truncated": false,
  "searched_trees": 1
}
```

A symbol search returns `{"symbols": [...], "truncated", "searched_trees"}`, each symbol with `tenant`, `tree`, `branch`, `snapshot_id`, `path`, `line`, `name`, `kind`, `container`, `signature`, `language` and `match` (`exact`, `prefix` or `substring`). `before`/`after` and `container` are omitted when empty, and hit text is cut at 1000 bytes. `truncated` is `true` when more results exist than `limit` or the **5 second** time budget ran out. `searched_trees` counts the trees actually searched.

`GET /api/v1/admin/code-index` returns the format version, memory use against the limit, loaded segments, evictions, disk use, builds and disk loads since start, and per tree its state (`ready`, `building` or `error`), files, bytes, symbols, branches and segments. The rebuild answers `{"rebuilt": n, "trees": [...]}` after it finished and is audited as `code_index.rebuild`.

Errors: `400 bad_request` (missing or short `q`, invalid regex, bad parameters or `kind`, `branch` together with `branches=all`, `tree` without a tenant), `404 not_found` (unknown tenant or tree), `401`/`403` (an explicit tree you may not read; admin endpoints without `server:admin`), `501 not_implemented` (code search disabled).
