There are three ways to get the server:

- **Release archives.** Every `worktree-<version>-<target>` archive built by `scripts/release.sh` (and the release workflow) contains `worktree-server` next to `wt` and `worktree-bg`, and `worktree-admin-<version>.tar.gz` holds the admin panel. `scripts/install.sh --with-server` (`install.ps1 -WithServer`) installs it with SHA-256 verification. See [Installing the clients](/docs/server/deployment#installing-the-clients).
- **Container image.** `deploy/docker/Dockerfile` builds an image with the server, the admin panel and `git`; Compose and Helm deployments use it. See [Deployment](/docs/server/deployment#docker).
- **Source.** The steps below.

<Callout type="info" title="Pre-1.0">
  W0rkTree is pre-1.0. Images and archives are produced per release tag; if none has been published for the version you need, build them locally or from source. Read the [changelog](/changelog) before upgrading.
</Callout>

## Requirements

| Requirement | Notes |
|---|---|
| Go 1.25 or newer | The server is pure Go (no cgo), so no C toolchain is needed. |
| Node.js 22 or newer | Only if you want to build and serve the admin panel. |
| A writable data directory | Defaults to `./wt-data` relative to the working directory. |

## Build

<Steps>
<Step>

### Get the source

Clone the W0rkTree repository and change into the server module:

```bash
cd services/server-go
```

</Step>
<Step>

### Compile the binary

<Tabs items={['bash', 'PowerShell']}>
<Tab value="bash">

```bash
go build -o worktree-server .
```

</Tab>
<Tab value="PowerShell">

```powershell
go build -o worktree-server.exe .
```

</Tab>
</Tabs>

Because the build is pure Go you can cross-compile, for example `GOOS=linux GOARCH=amd64 go build -o worktree-server .` (PowerShell: `$env:GOOS = 'linux'; $env:GOARCH = 'amd64'; go build -o worktree-server .`).

</Step>
<Step>

### Run it for the first time

Start the server with an admin password so the server admin account exists from the first boot:

<Tabs items={['bash', 'PowerShell']}>
<Tab value="bash">

```bash
./worktree-server --admin-password 'change-me-now'
```

</Tab>
<Tab value="PowerShell">

```powershell
.\worktree-server.exe --admin-password 'change-me-now'
```

</Tab>
</Tabs>

With no other flags the server listens on `:7420`, stores data in `./wt-data` (creating `meta.db` and `objects/`), allows self-service registration, and creates (or promotes) the account `admin` as server admin.

<Callout type="warn">
  Passing a password on the command line exposes it in shell history and process listings. Outside local testing, set `WT_ADMIN_PASSWORD` in the environment instead. See [Configuration](/docs/server/configuration).
</Callout>

</Step>
<Step>

### Verify

```bash
curl http://localhost:7420/healthz
```

```json
{"status":"ok","version":"0.2.0-dev","uptime_seconds":12,"checks":{"meta":"ok","objects":"ok"}}
```

The status is `degraded` (HTTP `503`) when the metadata store or the object store probe fails. See [Monitoring](/docs/server/monitoring#health-check).

On Windows PowerShell, `curl` is an alias for `Invoke-WebRequest`; use `curl.exe` or `Invoke-RestMethod`:

```powershell
Invoke-RestMethod http://localhost:7420/healthz
```

</Step>
<Step>

### Connect a client

Log in with `wt` and point a worktree at the server:

<Tabs items={['bash', 'PowerShell']}>
<Tab value="bash">

```bash
echo 'change-me-now' | wt login http://localhost:7420 -u admin --password-stdin
wt remote add origin http://localhost:7420 --tenant admin
wt push
```

</Tab>
<Tab value="PowerShell">

```powershell
'change-me-now' | wt login http://localhost:7420 -u admin --password-stdin
wt remote add origin http://localhost:7420 --tenant admin
wt push
```

</Tab>
</Tabs>

The tenant `admin` is the admin account's personal tenant (its slug equals the username). Accounts with two-factor authentication are asked for a code, or pass `--mfa-code` (`WT_MFA_CODE`). See [`wt login`](/docs/cli/remote#wt-login) and [`wt remote`](/docs/cli/remote#wt-remote).

Other users can now register themselves (`wt register`), or a server admin creates their accounts with `wt admin account-create USERNAME --email EMAIL` (see [`wt admin`](/docs/cli/administration#wt-admin)).

</Step>
</Steps>

## Serving the admin panel

The admin panel (`apps/admin`, React + Vite) is a static build that the server serves at `/admin/`.

<Tabs items={['bash', 'PowerShell']}>
<Tab value="bash">

```bash
cd apps/admin
npm install
npm run build
cd ../../services/server-go
./worktree-server --admin-dir ../../apps/admin/dist --admin-password 'change-me-now'
```

</Tab>
<Tab value="PowerShell">

```powershell
cd apps/admin
npm install
npm run build
cd ..\..\services\server-go
.\worktree-server.exe --admin-dir ..\..\apps\admin\dist --admin-password 'change-me-now'
```

</Tab>
</Tabs>

Open `http://localhost:7420/admin/` and sign in with the admin account. Paths under `/admin/` that do not match a file fall back to `index.html`, so client-side routes work on reload. If `--admin-dir` is not set, the server does not serve the panel.

For panel development, run `npm run dev` in `apps/admin` instead: the Vite dev server on `http://localhost:5173` proxies `/api` and `/healthz` to `http://localhost:7420`, and the server allows that origin for CORS. See the [admin panel guide](/guides/admin-panel).
