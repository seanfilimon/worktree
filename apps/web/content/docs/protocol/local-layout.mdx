Everything W0rkTree knows about a worktree lives in one `.wt/` directory at the worktree root. Per-user state (credentials and the daemon) lives separately in `$WT_HOME`. The authoritative description is the module documentation of `crates/worktree-sdk/src/repo/mod.rs`; this page expands on it.

<Callout type="info">
  The layout is managed by `worktree_sdk::Repository`. Use `wt` or the [SDK](/docs/sdk/repository) rather than editing files under `.wt/` by hand. The format may change before 1.0.
</Callout>

## The `.wt/` directory

```text
.wt/
  config.toml                 WorktreeConfig
  ignore                      extra ignore patterns (one per line)
  objects/<hh>/<62 hex>       blobs + manifests (ObjectStore)
  snapshots/<id>.json         Snapshot records
  trees/<tree>/tree.toml      TreeInfo (name, id, path, default branch, remote name)
  trees/<tree>/HEAD           current branch name
  trees/<tree>/refs/branches/<branch>        snapshot id (or empty)
  trees/<tree>/refs/branches.meta.json       created_at / archived flags
  trees/<tree>/refs/remotes/<remote>/<branch> snapshot id
  trees/<tree>/refs/tags/<tag>.json          TagInfo
  trees/<tree>/index.json     stat cache: path -> (size, mtime_ns, hash)
  trees/<tree>/reflog.jsonl   ReflogEntry per line (append-only)
  trees/<tree>/MERGE_STATE.json
  conflicts/<tree>.json       machine-readable conflict list during a merge
```

| Path | Contents |
|---|---|
| `config.toml` | Worktree configuration (`WorktreeConfig`, see below). |
| `ignore` | Extra ignore patterns for the whole worktree, one per line. `wt ignore add` appends here. |
| `objects/` | The content-addressed object store: blobs and manifests, stored raw at `objects/<hh>/<62 hex>`. Shared by all trees of the worktree. See [Object model](/docs/protocol/object-model). |
| `snapshots/<id>.json` | One JSON `Snapshot` record per snapshot, named by its UUID. Shared by all trees. |
| `trees/<tree>/tree.toml` | `TreeInfo` for one tree: name, id, path relative to the root (empty for the root tree), default branch, and server-side (remote) name. |
| `trees/<tree>/HEAD` | Name of the tree's current branch. |
| `trees/<tree>/refs/branches/<branch>` | The branch tip's snapshot id, or empty for a branch with no snapshots yet. Branch names may contain `/` (for example `feature/login`). |
| `trees/<tree>/refs/branches.meta.json` | Per-branch metadata: creation time and the `archived` flag. Archiving a branch sets the flag; the ref and its history stay. |
| `trees/<tree>/refs/remotes/<remote>/<branch>` | Last known server tip of `<branch>` on `<remote>`, updated by push, fetch, and pull. Revisions like `origin/main` resolve here. |
| `trees/<tree>/refs/tags/<tag>.json` | One `TagInfo` per tag: name, target snapshot, optional message, tagger, creation time. |
| `trees/<tree>/index.json` | Stat cache mapping each tracked path to its size, modification time (ns), and hash, so `wt status` can skip rehashing unchanged files. Safe to delete; it is rebuilt. |
| `trees/<tree>/reflog.jsonl` | Append-only log of every ref change, one JSON `ReflogEntry` per line. See below. |
| `trees/<tree>/MERGE_STATE.json` | Present only while a conflicted merge awaits resolution. See [Merge and diff](/docs/protocol/merge-and-diff#merge-state). |
| `conflicts/<tree>.json` | Machine-readable conflict list (each entry has `path` and `kind`) during a conflicted merge, for editors and scripts. |

### Reflog entries

Each line of `reflog.jsonl` is a `ReflogEntry`:

| Field | Meaning |
|---|---|
| `at` | Timestamp (UTC). |
| `tree`, `branch` | Tree and branch affected. |
| `action` | One of `init`, `snapshot`, `auto-snapshot`, `switch`, `branch.create`, `branch.archive`, `merge`, `fast-forward`, `revert`, `restore`, `pull`, `push`, `tag.create`, `tag.delete`. |
| `old`, `new` | Snapshot ids before and after (either may be null). |
| `message` | Human-readable description. |

The file is only ever appended to; `wt reflog` shows it newest first. See [Reflog and recovery](/guides/reflog-and-recovery).

## `config.toml`

`.wt/config.toml` is the serialized `worktree_sdk::config::WorktreeConfig`:

```toml
[worktree]
name = "my-project"            # worktree and root tree name
id = "4f9c2a1e-..."            # UUID, generated by init
created_at = "..."
default_branch = "main"

[user]
name = "Ada Lovelace"          # snapshot author: "name <email>"
email = "ada@example.com"

[auto_snapshot]
enabled = true                 # daemon auto-snapshots
inactivity_secs = 30           # snapshot after this many quiet seconds
max_changed_files = 50         # or immediately once this many files changed

[sync]
auto_stage = true              # daemon uploads auto-snapshots as staged WIP
remote = "origin"              # remote the daemon uses

[remote.origin]
url = "http://localhost:7420"  # server base URL (gRPC + REST)
tenant = "ada"                 # tenant slug on that server
```

| Section | Fields | Defaults |
|---|---|---|
| `[worktree]` | `name`, `id`, `created_at`, `default_branch` | `default_branch = "main"` |
| `[user]` | `name`, `email` | empty |
| `[auto_snapshot]` | `enabled`, `inactivity_secs`, `max_changed_files` | `true`, `30`, `50` |
| `[sync]` | `auto_stage`, `remote` | `true`, `"origin"` |
| `[remote.<name>]` | `url`, `tenant` | none; one table per named remote |

Every field is addressable as a dotted key (`user.name`, `remote.origin.url`, ...) through [`wt config`](/docs/cli/repository#wt-config) and `WorktreeConfig::get` / `set` / `entries`. There is no global configuration file; configuration is per worktree. See [Config model](/guides/config-model).

## Nested trees: `.wt-tree/`

A worktree always has a root tree (created by `wt init`). Additional **nested trees** are directories that contain a `.wt-tree/` marker directory; `wt tree add NAME PATH` registers one and writes `PATH/.wt-tree/config.toml`. Each tree also has its own `trees/<tree>/` directory under the root `.wt/`.

- A tree's snapshots exclude the paths of trees nested inside it, so each file belongs to exactly one tree.
- `.wt-tree/` markers themselves are never snapshotted.
- When no tree is named, commands act on the deepest tree whose directory contains the current path, falling back to the root tree (`Repository::tree_for_path`).
- Removing a nested tree unregisters it and keeps its files. The root tree cannot be removed.

See [Nested trees](/guides/nested-trees).

## Per-user state: `$WT_HOME`

`$WT_HOME` defaults to `~/.wt` (`%USERPROFILE%\.wt` on Windows; resolved from `HOME`, then `USERPROFILE`). Set the `WT_HOME` environment variable to use another directory, for example a temporary one in tests.

| File | Written by | Contents |
|---|---|---|
| `credentials.toml` | `wt login`, `wt register`, `wt logout` | One entry per normalized server URL (no trailing slash), each with `username` and `token`. |
| `bg.json` | `worktree-bg` | `{"pid": u32, "port": u16, "version": "..."}`. Written on startup, removed on clean shutdown. The CLI uses it to find the daemon. |
| `bg.toml` | `worktree-bg` | `watched = ["path", ...]`: watched worktree roots, persisted on watch / unwatch. |
| `bg.log` | `worktree-bg` | Daemon log. |

<Callout type="warn">
  `credentials.toml` holds bearer tokens. Keep `$WT_HOME` private to your user and never commit it. See [Security](/docs/security#local-credential-file).
</Callout>

## Ignore rules

A path is never snapshotted if it matches an ignore pattern. Patterns are combined from three sources (`Repository::ignore_patterns`):

1. **Built-ins**, always active:

   ```text
   .wt/
   .wt-tree/
   .git/
   target/
   node_modules/
   .DS_Store
   *.swp
   ```

2. **`.wt/ignore`**, local to the worktree (`wt ignore add` appends here; `wt git import` converts `.gitignore` into it).
3. **`.wtignore`** files in the working directory.

Patterns use gitignore-style syntax, implemented by `worktree_protocol::feature::ignore`:

| Syntax | Meaning |
|---|---|
| blank line, `# comment` | Ignored. |
| `name` (no `/`) | Matches a file or directory name at any depth, e.g. `*.log`. |
| `dir/` | Trailing `/`: matches directories only. |
| `a/b` (contains `/`) | Anchored: matched against the full `/`-separated path. |
| `*` | Any run of characters within one path segment. |
| `**` | Zero or more path segments, e.g. `**/build`. |
| `?` | One character other than `/`. |
| `!pattern` | Negation: re-includes a path excluded by an earlier pattern. |

Paths are always matched with `/` separators, also on Windows. Check a path with [`wt ignore check`](/docs/cli/repository#wt-ignore) or `Repository::is_ignored`. See [Ignore patterns](/guides/ignore-patterns).
