W0rkTree's components agree on a small set of contracts. The Rust client (`wt`, `worktree-bg`, `worktree-sdk`) and the Go server (`services/server-go`) share a gRPC service definition and a byte-exact object format, so a push or pull is a byte copy of content-addressed objects plus a list of snapshot records.

## What is specified where

| Contract | Source of truth | Documented in |
|---|---|---|
| Client ⇄ server sync (gRPC service, messages, push/pull flows) | `crates/worktree-protocol/proto/sync.proto` | [Sync protocol](/docs/protocol/sync-protocol) |
| Object hashing, blobs, manifests, snapshot records, tags, branch tips | `sync.proto`, `crates/worktree-sdk/src/{model,store}.rs` | [Object model](/docs/protocol/object-model) |
| Local repository layout (`.wt/`), configuration, ignores, `$WT_HOME` | `crates/worktree-sdk/src/{repo/mod,config}.rs` | [Local layout](/docs/protocol/local-layout) |

| REST API and Server-Sent Events | `services/server-go/internal/domain` | [REST API](/docs/server/rest-api), [Events](/docs/server/events) |

## Transport at a glance

- **One port.** The server serves gRPC and REST/SSE/static files on a single listener, default `:7420`. Remote URLs look like `http://localhost:7420`; the same base URL is used for gRPC and REST.
- **gRPC over h2c.** Sync uses gRPC on cleartext HTTP/2. Authentication uses REST (`/api/v1/auth/*`); the resulting bearer token is sent on every gRPC call as `authorization: Bearer <token>` metadata.
- **64 MiB messages.** The gRPC maximum message size is 64 MiB in both directions.
- **TLS** is provided by a reverse proxy in front of the server, not by the server itself.

<Callout type="warn" title="Roadmap">
  A QUIC transport, built-in TLS, and chunked (FastCDC) large-file transfer on the wire are not part of v0.2.0. Objects are transferred whole in `ObjectData` messages.
</Callout>

## Versioning

The protobuf package is **`worktree.sync.v1`** and the service is `worktree.sync.v1.SyncService`. Within `v1`, changes are additive only:

- Field numbers are never reused or renumbered; new fields get new numbers.
- Every message reserves field tags `100` to `199` for future expansion.
- IDs are wrapped messages (`TreeId`, `SnapshotId`, `BranchId`, `TenantId`, `AccountId`, `ContentHash`) for type safety across Rust and Go.
- Timestamps use `google.protobuf.Timestamp`. Enums start with an `_UNSPECIFIED = 0` value.

A breaking change would ship as a new package (`worktree.sync.v2`). The server reports its version in `PingResponse.server_version` and in `GET /healthz`.

Rust code is generated by the `worktree-protocol` build script (with a vendored `protoc`); Go code is regenerated with `bash scripts/gen-proto.sh` into `services/server-go/internal/proto/syncpb`.
