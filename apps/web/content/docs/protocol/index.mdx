W0rkTree's components agree on a small set of contracts. The Rust client (`wt`, `worktree-bg`, `worktree-sdk`) and the Go server (`services/server-go`) share a gRPC service definition and a byte-exact object format, so a push or pull is a byte copy of content-addressed objects plus a list of snapshot records.

These pages summarize the protocol. The normative text is the set of specifications in [`crates/worktree-protocol/specs`](https://github.com/seanfilimon/worktree/tree/main/crates/worktree-protocol/specs), each of which ends with an **Implementation status** and a **Roadmap** section.

## Transport at a glance

- **One port.** The server serves gRPC and REST/SSE/static files on a single listener, default `:7420`. Remote URLs look like `http://localhost:7420`; the same base URL is used for gRPC and REST.
- **gRPC over HTTP/2.** Cleartext h2c by default; TLS with ALPN `h2` on the same port when the server runs with `--tls-cert`/`--tls-key` (optional mTLS with `--tls-client-ca`). Clients use `https://` remote URLs for TLS. See [Operations](/docs/server/operations#tls).
- **Bearer tokens.** Authentication uses REST (`/api/v1/auth/*`); the resulting token is sent on every gRPC call as `authorization: Bearer <token>` metadata.
- **64 MiB messages.** The gRPC maximum message size is 64 MiB in both directions. Files over 8 MiB are split into content-defined chunks, so a large file never needs one large message.

- **Packs (v0.8).** Pushes, fetches and clones move objects as one pack with copy/insert deltas and zstd payloads; uploads are resumable. Whole `ObjectData` messages (gzip-compressed since v0.6) remain the fallback. Objects are always stored whole (zstd-compressed) on disk. See [Pack and delta transfer](/docs/protocol/packs).

<Callout type="info" title="Not built yet">
  A QUIC transport is described in earlier designs but is not built (see the [roadmap](/roadmap)).
</Callout>

## Versioning

The protobuf package is **`worktree.sync.v1`** and the service is `worktree.sync.v1.SyncService`. Within `v1`, changes are additive only:

- Field numbers are never reused or renumbered; new fields, enum values and RPCs get new numbers. (`CHUNK_LIST`, snapshot dependencies and signatures, `stubbed_paths`, `WatchBranches`, `Unstage`, `GetAccessConfig` and, in v0.8, `PushRequest.force` / `operation_id`, staged `label`s, the pack RPCs and `DeleteTag` were all added this way.)
- Every message reserves field tags `100` to `199` for future expansion.
- IDs are wrapped messages (`TreeId`, `SnapshotId`, `BranchId`, `TenantId`, `AccountId`, `ContentHash`) for type safety across Rust and Go. `BranchId.value` carries the branch name.
- Timestamps use `google.protobuf.Timestamp`. Enums start with an `_UNSPECIFIED = 0` value.

A breaking change would ship as a new package (`worktree.sync.v2`). The server reports its version in `PingResponse.server_version` and in `GET /healthz`. Local stored records gain fields the same way: new fields default when absent, so newer clients read older `.wt/` directories unchanged.

Rust code is generated by the `worktree-protocol` build script (with a vendored `protoc`); Go code is regenerated with `bash scripts/gen-proto.sh` into `services/server-go/internal/proto/syncpb`.
