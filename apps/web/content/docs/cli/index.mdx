`wt` is the W0rkTree command-line client (crate `worktree-cli`). It works on a local `.wt/` repository through the Rust SDK, talks to a W0rkTree server over gRPC and REST on a single port, and controls the background daemon `worktree-bg` over newline-delimited JSON on a loopback (`127.0.0.1`) TCP port.

These pages are task-oriented: each command is described with its common flags and examples. The complete, generated flag listing for every command is in [`docs/cli-reference.md`](https://github.com/seanfilimon/worktree/blob/main/docs/cli-reference.md) (produced from `wt --help`).

<Callout type="info" title="Installing wt">
Since v0.7, `scripts/install.sh` (Linux, macOS, Git Bash) and `scripts/install.ps1` (Windows PowerShell) download the release archive for your OS and architecture, verify its SHA-256 against the release's `SHA256SUMS`, and install `wt` and `worktree-bg`. Building from source (`cargo install --path crates/worktree-cli` and `cargo install --path crates/worktree-bg`) still works. See [Installation](/docs/installation).
</Callout>

## Synopsis

```text
wt [--json] [-C <path>] [--tree <name>] [--no-color] [--server <url>] <command> [args...]
```

## Global flags

Global flags are accepted by every command and may appear anywhere on the command line.

| Flag | Description |
|---|---|
| `--json` | Print exactly one machine-readable JSON document on stdout instead of human output. Errors go to stderr. |
| `-C <path>` | Run as if `wt` had been started in `<path>`. The worktree is found by walking up from this directory to the nearest `.wt/`. |
| `--tree <name>` | Operate on the named tree instead of the tree inferred from the current directory. |
| `--no-color` | Disable colored output. Colors are also off when stdout is not a terminal or `NO_COLOR` is set. |
| `--server <url>` | Server for server-side commands (`wt mr`, `wt trees`, `wt team`, ...). Env `WT_SERVER`. Default: this worktree's origin remote, else the only saved login. |
| `-h`, `--help` | Show help for the command. |
| `-V`, `--version` | Print the version. |

### Which tree a command acts on

A worktree contains one root tree (created by `wt init`) and optionally nested trees (directories with a `.wt-tree/` marker, see [`wt tree`](/docs/cli/repository#wt-tree)). Tree-scoped commands such as `wt status`, `wt snapshot`, `wt log` or `wt push` act on:

1. the tree named by `--tree <name>`, if given; otherwise
2. the deepest tree whose directory contains the current directory (or the `-C` path); falling back to
3. the root tree.

### Server-side commands

Commands that manage server state (`wt tenant`, `wt trees`, `wt fork`, `wt mr`, `wt ci`, `wt protect`, `wt owners`, `wt license`, `wt compliance`, `wt todo`, `wt deps`, `wt release`, `wt webhook`, `wt mirror`, `wt inbox`, `wt search`, the IAM commands including `wt attr`, `wt admin`, `wt audit`, `wt api`, ...) talk to the REST API. They resolve the server from `--server` / `WT_SERVER`, else the worktree's origin remote, else the only saved login. `TREE` arguments are written `tenant/tree`; inside a worktree they default to the origin tenant plus the current tree's remote name.

```bash
wt mr list                              # the current tree on origin
wt mr list acme/payments                # an explicit tree
wt --server https://wt.example.com trees list --tenant acme
```

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Success. |
| `1` | The command failed (for example: not a worktree, branch not found, push rejected, secrets detected (`wt compliance scan`), server unreachable, `wt doctor` or `wt fsck` found errors, `wt api` got a non-2xx response, a diverged branch in `wt fork sync`, invalid files in `wt trees config validate`, `wt license audit --strict` problems). |
| `2` | Usage error: unknown command or flag, missing or conflicting arguments, an alias that cannot be expanded. |
| `3` | Conflicts: a merge, cherry-pick, rebase or stash apply stopped with conflicts (`wt merge`, `wt pull`, `wt sync`, `wt cherry-pick`, `wt rebase`, `wt stash apply/pop`, an auto-stash on `wt switch`), `--continue` found unresolved conflict markers, a server-side merge was refused with conflicts (`wt mr merge`), or `wt mr resolve` found leftover conflict markers. |

## Environment variables

| Variable | Description |
|---|---|
| `WT_HOME` | Per-user state directory. Default `~/.wt` (on Windows, `%USERPROFILE%\.wt`). |
| `WT_PASSWORD` | Password used by `wt login` and `wt register` instead of an interactive prompt. |
| `WT_MFA_CODE` | TOTP or recovery code for `wt login` on accounts with two-factor authentication. |
| `WT_TOKEN` | Bearer token (API token or service-account key) used for every server instead of saved logins, for example in CI. `WT_TOKEN_USER` optionally names the account for display. |
| `WT_SERVER` | Server for server-side commands (same as `--server`). |
| `NO_COLOR` | Disable colors (same as `--no-color`). |
| `WT_LOG` | Diagnostic logging on stderr, for example `WT_LOG=debug` or `WT_LOG=worktree_sdk=trace`. |
| `WT_NO_PACK` | v0.8: `1` (or `true` / `yes`) transfers whole objects instead of [packs](/docs/protocol/packs) for push, fetch, pull and clone. |
| `WT_NO_BROWSER` | v0.8: `wt login --device` only prints the URL instead of opening a browser. |
| `BROWSER` | Browser command used by `wt login --device` and `wt open`; default the platform opener. |

Passwords are read from the first line of stdin with `--password-stdin`, else from `WT_PASSWORD`, else from an interactive prompt that does not echo.

Files in `$WT_HOME`:

| File | Contents |
|---|---|
| `credentials.toml` | Saved credentials, keyed by normalized server URL (written by `wt login` / `wt register`, removed by `wt logout`): the access `token` and, since v0.8, `refresh_token` and `expires_at`, renewed transparently. |
| `config.toml` | User-level defaults: `[user]`, `[signing]`, `[secret_scanning]`, `[alias]`. See [Configuration](/docs/cli/configuration#configuration-hierarchy). |
| `keys/<name>.key`, `keys/<name>.pub` | Ed25519 snapshot-signing keys created by [`wt identity generate`](/docs/cli/signing). |
| `bg.json` | `pid`, `port`, `version` and the random IPC `token` of the running daemon; written on daemon start, removed on clean shutdown. |
| `bg.toml` | `watched = [...]`, the worktree roots the daemon watches. |
| `bg.log` | Daemon log (rotated to `bg.log.old` above 10 MiB). |

<Callout type="warn" title="Tests and CI">
Set `WT_HOME` to a temporary directory in tests and CI so runs never read or overwrite your real credentials, keys or daemon state.
</Callout>

## Revision syntax

Wherever a command takes `REV` (`wt log`, `wt show`, `wt diff`, `wt blame --rev`, `wt revert`, `wt restore --from`, `wt branch create --from`, `wt tag create`, `wt archive`, `wt merge`, `wt cherry-pick`, `wt rebase`, `wt open snapshot`), the following forms are accepted. Revisions resolve within the selected tree.

| Form | Resolves to |
|---|---|
| `HEAD`, `@` | Head snapshot of the current branch. |
| `<branch>` | Tip of a local branch. |
| `origin/<branch>` | Last known tip of a remote branch (from `refs/remotes/origin/<branch>`, updated by `wt fetch`, `wt pull`, `wt push`). Any remote name works. |
| `<tag>` | The snapshot a tag points to. |
| `<id-prefix>` | A snapshot id (UUID) or a unique prefix of at least 4 characters. An ambiguous prefix is an error. |
| `REV~N` | The `N`th first-parent ancestor, for example `HEAD~2`, `main~1`. |
| `REV^N` | The `N`th parent (`^` = `^1`), for example the second parent of a merge: `HEAD^2`. Suffixes chain: `main~2^2`. |
| `@{N}` | The `N`th newest reflog entry of the current branch. |
| `BRANCH@{N}` | The `N`th newest reflog entry of that branch; `HEAD@{N}` counts entries of the whole tree. `main@{1}~2` works. |

Snapshot ids are UUID v4 strings; human output usually shows the first 8 characters.

## Scripting with `--json`

- `--json` puts the command's result on stdout as one JSON document. Field names follow the SDK data types (for example `wt status --json` mirrors `StatusReport`: `tree`, `branch`, `head`, `changes` with `path` and `kind` of `added`, `modified` or `deleted`, and `merge`, plus `restricted` and `shallow`). Server-side commands print the server's JSON. See [SDK repository](/docs/sdk/repository).
- Branch on the **exit code**, not on message text: `0` success, `1` error, `2` usage, `3` conflicts.
- Never type passwords into scripts interactively. Use `--password-stdin` or `WT_PASSWORD`. In CI, set `WT_TOKEN` to a scoped API token or service-account key instead of logging in (see [`wt token`](/docs/cli/iam#wt-token) and [`wt sa`](/docs/cli/iam#wt-sa)); otherwise `wt` uses the tokens saved in `$WT_HOME/credentials.toml`. For endpoints without a dedicated command, use [`wt api`](/docs/server/openapi#wt-api).
- Run `wt doctor --offline` (or `wt doctor` with network checks) as a setup check; it exits `1` on errors.
- Destructive commands ask for confirmation; pass `--yes` (or `-y`) when stdin is not a terminal.
- Use `-C <path>` instead of changing directories, and `--tree <name>` instead of relying on the current directory.

```bash
# Fail a CI step when the working tree is dirty
changes=$(wt -C ./repo status --json | jq '.changes | length')
if [ "$changes" -ne 0 ]; then echo "uncommitted changes"; exit 1; fi

# Handle merge conflicts explicitly
wt merge feature/login
case $? in
  0) echo "merged" ;;
  3) echo "conflicts; run wt merge status" ;;
  *) echo "merge failed"; exit 1 ;;
esac
```

```powershell
$status = wt -C .\repo status --json | ConvertFrom-Json
if ($status.changes.Count -ne 0) { Write-Error "uncommitted changes"; exit 1 }

wt merge feature/login
if ($LASTEXITCODE -eq 3) { wt merge status }
```

<Callout type="info">
JSON output is pre-1.0. Field names track the SDK and server types and may change between versions.
</Callout>
