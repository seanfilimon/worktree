`wt git` is a one-shot bridge between Git and W0rkTree, implemented by the `worktree-git` crate (libgit2). It reads and writes Git repositories on disk; it does not talk to Git hosting servers.

## `wt git`

```text
wt git import GIT_PATH [DEST] | export GIT_PATH [--rev REV]
```

| Subcommand | Description |
|---|---|
| `import GIT_PATH [DEST]` | Create a new worktree from the Git repository at `GIT_PATH`. |
| `export GIT_PATH [--rev REV]` | Write snapshots into the Git repository at `GIT_PATH` as Git commits. |

## `wt git import`

```text
wt git import GIT_PATH [DEST]
```

| Argument | Description |
|---|---|
| `GIT_PATH` | Path to an existing Git repository. |
| `DEST` | Directory for the new worktree. The worktree is named after this directory. Pass it explicitly to control where the worktree is created. |

What is imported:

- **Branches**: every local Git branch. Each branch's commit graph becomes snapshots on the **root tree**, preserving parent links (merge commits become two-parent snapshots), author, timestamp and message.
- **Tags**: lightweight and annotated tags become W0rkTree tags.
- **Ignore rules**: `.gitignore` is converted into `.wt/ignore` (the syntax is the same).
- **Files**: blobs are re-hashed with BLAKE3 into the W0rkTree object store.

After import, one branch is checked out in the working directory.

```bash
wt git import ~/src/legacy-app ./legacy-app
cd legacy-app
wt log -n 5 --oneline
wt branch
```

```powershell
wt git import C:\src\legacy-app .\legacy-app
wt -C .\legacy-app log -n 5 --oneline
```

## `wt git export`

```text
wt git export GIT_PATH [--rev REV]
```

| Argument / flag | Description |
|---|---|
| `GIT_PATH` | Target Git repository. Created if it does not exist. |
| `--rev REV` | Revision to export. Default: all branches of the tree. |

Snapshots are written as Git commits with the same parents, author, timestamp and message. The tree to export is the root tree unless `--tree <name>` is given. The mapping between snapshot ids and Git commit SHAs is stored in `.wt/git-map.json`, so **repeated exports are incremental and deterministic**: already-exported snapshots are skipped and produce the same commits.

```bash
wt git export ../legacy-app-git
wt git export ../legacy-app-git --rev main
wt --tree frontend git export ../frontend-git
```

## Limitations

<Callout type="warn">
Be aware of these limits of the v0.2.0 bridge before migrating.
</Callout>

- **One-shot, not a mirror.** Import and export are explicit commands. There is no live Git mirror mode; it is on the [roadmap](/roadmap).
- **Local branches only.** Import reads local branches. Remote-tracking branches (`origin/*` in Git) are not imported; check out the branches you need in Git first.
- **Everything lands in the root tree.** Imported history goes to the root tree. Git submodules are not turned into nested trees by the import contract; set up nested trees afterwards with [`wt tree add`](/docs/cli/repository#wt-tree).
- **Ids differ.** Git uses SHA-1 commit ids, W0rkTree uses UUID snapshot ids and BLAKE3 object hashes. Use `.wt/git-map.json` to correlate them.
- **Commits, tags and ignore rules only.** Hooks, Git config, stashes, the Git index and Git reflogs are not part of the import. `.gitattributes` filters (including Git LFS pointers) are not applied, so LFS files arrive as their pointer files.
- **No Git remote transport.** Push to a Git host with `git push` from the exported repository.

See [Git interop](/guides/git-interop) and [Migration](/guides/migration) for complete workflows.
